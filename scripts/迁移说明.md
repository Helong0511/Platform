# 数据迁移说明

## 概述

本脚本用于将旧的SQL文件（`platform_old.sql`）中的数据迁移到当前项目中。

## 主要处理

### 1. 表结构差异处理

- **country_info → countries**: 
  - 旧表名 `country_info` 改为新表名 `countries`
  - 字段映射：`iso_code_2` → `alpha_2_code`, `iso_code_3` → `alpha_3_code`, `iso_code_numeric` → `numeric_code`
  - 字段映射：`name_en` → `country_name_en`, `name_zh` → `country_name_zh`

- **clients 表**:
  - 旧表有 `chat_id` 字段，新表没有，迁移时跳过该字段

- **ad_data 表**:
  - 新表增加了 `country_code` 字段，旧数据没有，迁移时设为 `NULL`

### 2. 数据完整性

- 自动验证外键关系（如 `user_id`, `client_id`, `product_id` 等）
- 跳过不存在的关联记录
- 支持跳过已存在的记录（默认启用）

## 使用方法

### 基本用法

```bash
# 使用默认SQL文件路径（scripts/platform_old.sql）
python scripts/migrate_from_old_sql.py

# 指定SQL文件路径
python scripts/migrate_from_old_sql.py scripts/platform_old.sql

# 不跳过已存在的记录（会尝试更新，但可能因唯一约束失败）
python scripts/migrate_from_old_sql.py --no-skip-existing
```

### 参数说明

- `sql_file`: SQL文件路径（可选，默认为 `scripts/platform_old.sql`）
- `--skip-existing`: 跳过已存在的记录（默认启用）
- `--no-skip-existing`: 不跳过已存在的记录

## 迁移顺序

脚本按以下顺序迁移数据，确保外键依赖关系：

1. **countries** (country_info) - 国家信息
2. **users** - 用户
3. **clients** - 客户
4. **products** - 产品
5. **ad_data** - 广告数据
6. **product_assignments** - 产品分配
7. **scheduled_tasks** - 定时任务
8. **user_audit_logs** - 用户审计日志
9. **user_sessions** - 用户会话
10. **token_blacklist** - Token黑名单

## 注意事项

1. **数据库连接**: 确保 `.env` 文件中的 `DATABASE_URL` 配置正确
2. **表结构**: 脚本会自动创建表（如果不存在），但不会删除现有数据
3. **数据冲突**: 如果存在唯一约束冲突，会跳过该记录并记录错误
4. **外键验证**: 如果关联记录不存在，会跳过该记录并记录警告

## 故障排除

### 1. 连接数据库失败

检查 `.env` 文件中的 `DATABASE_URL` 配置：
```
DATABASE_URL=mysql+aiomysql://用户名:密码@主机:端口/数据库名
```

### 2. 表已存在错误

如果表已存在且有数据，脚本会跳过已存在的记录。如果需要清空表，请手动执行：
```sql
TRUNCATE TABLE table_name;
```

### 3. 外键约束错误

如果遇到外键约束错误，检查：
- 关联表的数据是否已迁移
- 外键值是否存在

### 4. 唯一约束冲突

如果遇到唯一约束冲突，脚本会跳过该记录。检查：
- 是否已存在相同的数据
- 是否需要更新而不是插入

## 回滚

如果需要回滚迁移，可以：

1. **删除迁移的数据**:
   ```sql
   DELETE FROM ad_data;
   DELETE FROM product_assignments;
   DELETE FROM products;
   DELETE FROM clients;
   DELETE FROM users;
   -- 注意：按依赖关系的逆序删除
   ```

2. **恢复数据库备份**（如果有）

## 技术支持

如有问题，请检查：
1. 日志输出中的错误信息
2. 数据库连接配置
3. SQL文件格式是否正确
