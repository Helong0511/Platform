# 国家代码SQL文件对比分析报告

## 一、表结构对比

### 文件1: `国家代码.sql` - `country_info` 表
- **字段数**: 6个
- **字段列表**:
  1. `id` - 自增主键
  2. `iso_code_2` - ISO 3166-1 二字母代码
  3. `iso_code_3` - ISO 3166-1 三字母代码
  4. `iso_code_numeric` - ISO 3166-1 数字代码
  5. `name_en` - 国家/地区英文名称
  6. `name_zh` - 国家/地区中文名称

### 文件2: `ISO3166-1.sql` - `countries` 表
- **字段数**: 11个
- **字段列表**:
  1. `id` - 自增主键
  2. `alpha_2_code` - 国家二字代码 (对应文件1的iso_code_2)
  3. `alpha_3_code` - 国家三字代码 (对应文件1的iso_code_3)
  4. `numeric_code` - 国家数字代码 (对应文件1的iso_code_numeric)
  5. `country_name_zh` - 国家中文名称 (对应文件1的name_zh)
  6. `country_name_en` - 国家英文名称 (对应文件1的name_en)
  7. `official_name_zh` - 官方中文名称 ⭐ **文件2独有**
  8. `official_name_en` - 官方英文名称 ⭐ **文件2独有**
  9. `independent_status` - 是否独立国家 ⭐ **文件2独有**
  10. `continent` - 所属大洲 ⭐ **文件2独有**
  11. `subregion` - 所属地区 ⭐ **文件2独有**

### 字段映射关系
| 文件1字段 | 文件2字段 |
|----------|----------|
| iso_code_2 | alpha_2_code |
| iso_code_3 | alpha_3_code |
| iso_code_numeric | numeric_code |
| name_en | country_name_en |
| name_zh | country_name_zh |

## 四、主要差异总结

### 1. 表结构差异
- **文件2更完整**: 包含官方名称、独立状态、大洲和地区等额外信息
- **文件1更简洁**: 只包含基本的ISO代码和名称信息

### 2. 数据完整性
- **文件2更规范**: 使用标准的ISO 3166-1英文名称格式
- **文件1更简洁**: 使用简化的英文名称

### 3. 特殊记录处理
- **文件1**: 将"全部国家"和"未知区域"放在开头（ZZ和AA）
- **文件2**: 将"全部区域"和"未知区域"放在末尾（ZZ和AA），且数字代码不同

### 4. 数据量
- **文件1**: 268条记录（包含更多特殊/非标准记录）
- **文件2**: 251条记录（更符合ISO 3166-1标准）

## 五、建议

1. **如果只需要基本国家代码信息**: 使用文件1 (`country_info`)
2. **如果需要完整的地理和官方信息**: 使用文件2 (`countries`)
3. **建议统一**: 根据业务需求选择其中一个作为标准，避免数据不一致
