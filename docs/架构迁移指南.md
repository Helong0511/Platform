# 架构迁移指南

## 📋 概述

本指南帮助您将现有endpoint迁移到新的架构模式，使用统一的装饰器、查询构建器、响应格式等。

## 🎯 迁移原则

1. **渐进式迁移**：不需要一次性迁移所有代码，可以逐步进行
2. **保持兼容**：新架构与现有代码兼容，可以共存
3. **测试优先**：迁移前确保有测试覆盖，迁移后验证功能

## 📝 迁移步骤

### 步骤1：识别可迁移的endpoint

查找以下模式的代码：
- 直接使用 `select()` 构建查询
- 手动进行权限检查
- 手动构建响应格式
- 业务逻辑写在endpoint中

### 步骤2：创建/更新服务层方法

将业务逻辑移到服务层：

```python
# app/services/user_service.py
class UserService(BaseService[User]):
    async def get_users_paginated(
        self,
        page: int = 1,
        page_size: int = 20,
        search: Optional[str] = None,
        is_active: Optional[bool] = None,
        current_user: User
    ) -> Tuple[List[User], int]:
        """获取用户列表（带权限检查）"""
        # 权限检查
        if current_user.role != UserRole.ADMIN:
            # 非管理员只能查看自己的数据
            filters = {"created_by": current_user.id}
        else:
            filters = {}
        
        if is_active is not None:
            filters["is_active"] = is_active
        
        # 使用仓储层查询
        return await self.repository.paginated(
            page=page,
            page_size=page_size,
            filters=filters,
            search_fields=["username", "email", "full_name"],
            search_keyword=search,
            order_by_field="created_at"
        )
```

### 步骤3：更新endpoint使用新架构

**重构前**：
```python
@router.get("/users", response_model=ResponseBaseSchema[list[UserResponse]])
async def get_users(
    page: int = Query(1, ge=1),
    page_size: int = Query(20, ge=1, le=100),
    search: Optional[str] = Query(None),
    is_active: Optional[bool] = Query(None),
    db: AsyncSession = Depends(get_db),
    current_user: User = Depends(get_current_user)
):
    # 权限检查
    if current_user.role != UserRole.ADMIN:
        raise_api_exception(ErrorCode.FORBIDDEN, ...)
    
    # 构建查询
    query = select(User)
    filters = {}
    if is_active is not None:
        filters["is_active"] = is_active
        query = query.where(User.is_active == is_active)
    
    if search:
        query = query.where(or_(
            User.username.like(f"%{search}%"),
            User.email.like(f"%{search}%"),
            User.full_name.like(f"%{search}%")
        ))
    
    # 计数
    count_query = select(func.count(User.id))
    if filters:
        for key, value in filters.items():
            count_query = count_query.where(getattr(User, key) == value)
    if search:
        count_query = count_query.where(or_(
            User.username.like(f"%{search}%"),
            User.email.like(f"%{search}%"),
            User.full_name.like(f"%{search}%")
        ))
    
    total_result = await db.execute(count_query)
    total = total_result.scalar() or 0
    
    # 分页
    query = query.order_by(User.created_at.desc())
    query = query.offset((page - 1) * page_size).limit(page_size)
    
    result = await db.execute(query)
    users = result.scalars().all()
    
    return ResponseBaseSchema.success(
        data=[UserResponse.model_validate(u) for u in users],
        message="查询成功"
    )
```

**重构后**：
```python
from app.core.decorators import require_admin, validate_pagination
from app.core.dependencies import UserServiceDep
from app.core.response import create_paginated_response

@router.get("/users", response_model=ResponseBaseSchema[PaginatedResponse[UserResponse]])
@require_admin  # 使用装饰器进行权限检查
@validate_pagination(max_page_size=100)  # 使用装饰器验证分页参数
async def get_users(
    page: int = Query(1, ge=1),
    page_size: int = Query(20, ge=1, le=100),
    search: Optional[str] = Query(None),
    is_active: Optional[bool] = Query(None),
    user_service: UserServiceDep,  # 使用服务依赖
    current_user: User = Depends(get_current_user)
):
    # 业务逻辑在服务层
    users, total = await user_service.get_users_paginated(
        page=page,
        page_size=page_size,
        search=search,
        is_active=is_active,
        current_user=current_user
    )
    
    # 使用统一响应格式
    return create_paginated_response(
        items=[UserResponse.model_validate(u) for u in users],
        total=total,
        page=page,
        page_size=page_size
    )
```

### 模式1：简单查询迁移

```python
@router.get("/users/{user_id}")
async def get_user(
    user_id: int,
    db: AsyncSession = Depends(get_db),
    current_user: User = Depends(get_current_user)
```

### 模式2：创建操作迁移

**重构前**：
```python
@router.post("/users")
async def create_user(
    user_data: UserCreate,
    db: AsyncSession = Depends(get_db),
    current_user: User = Depends(get_current_user)
):
    # 权限检查
    if current_user.role != UserRole.ADMIN:
        raise_api_exception(ErrorCode.FORBIDDEN, ...)
    
    # 验证唯一性
    existing = await db.execute(
        select(User).where(User.username == user_data.username)
    )
    if existing.scalar_one_or_none():
        raise_api_exception(ErrorCode.USER_EXISTS, ...)
    
    # 创建用户
    user = User(**user_data.model_dump())
    user.password_hash = hash_password(user_data.password)
    db.add(user)
    await db.commit()
    await db.refresh(user)
    
    return ResponseBaseSchema.success(data=UserResponse.model_validate(user))
```

**重构后**：
```python
@router.post("/users")
@require_admin
async def create_user(
    user_data: UserCreate,
    user_service: UserServiceDep,
    current_user: User = Depends(get_current_user)
):
    user = await user_service.create_user(user_data, current_user)
    return create_success_response(
        data=UserResponse.model_validate(user),
        message="用户创建成功"
    )
```

### 模式3：更新操作迁移

**重构前**：
```python
@router.put("/users/{user_id}")
async def update_user(
    user_id: int,
    user_data: UserUpdate,
    db: AsyncSession = Depends(get_db),
    current_user: User = Depends(get_current_user)
):
    # 权限检查
    if current_user.role != UserRole.ADMIN and current_user.id != user_id:
        raise_api_exception(ErrorCode.FORBIDDEN, ...)
    
    # 查询用户
    result = await db.execute(
        select(User).where(User.id == user_id)
    )
    user = result.scalar_one_or_none()
    if not user:
        raise_api_exception(ErrorCode.USER_NOT_FOUND, ...)
    
    # 更新用户
    for key, value in user_data.model_dump(exclude_unset=True).items():
        setattr(user, key, value)
    
    await db.commit()
    await db.refresh(user)
    
    return ResponseBaseSchema.success(data=UserResponse.model_validate(user))
```

**重构后**：
```python
@router.put("/users/{user_id}")
async def update_user(
    user_id: int,
    user_data: UserUpdate,
    user_service: UserServiceDep,
    current_user: User = Depends(get_current_user)
):
    user = await user_service.update_user(user_id, user_data, current_user)
    return create_success_response(
        data=UserResponse.model_validate(user),
        message="用户更新成功"
    )
```

### Endpoint检查清单
- [ ] 使用装饰器进行权限检查
- [ ] 使用服务依赖注入
- [ ] 使用统一响应格式
- [ ] 参数验证使用Pydantic

### 仓储层检查清单
- [ ] 使用查询构建器
- [ ] 支持关联预加载
- [ ] 使用flush而非commit（由服务层控制事务）
- [ ] 提供必要的查找方法

## 🚀 迁移优先级

### 高优先级（建议先迁移）
1. **高频访问的endpoint**：如用户列表、产品列表等
2. **复杂的查询逻辑**：可以从查询构建器中获得最大收益
3. **权限检查复杂的endpoint**：使用装饰器可以大幅简化代码

### 中优先级
1. **CRUD操作**：统一模式，迁移相对简单
2. **统计查询**：可以使用查询构建器优化

### 低优先级
1. **简单的查询**：迁移收益较小
2. **即将废弃的功能**：可能不需要迁移

## ⚠️ 注意事项

1. **事务管理**：
   - 仓储层使用 `flush()` 而不是 `commit()`
   - 事务提交由服务层或endpoint控制
   - 确保异常时正确回滚

2. **缓存失效**：
   - 如果使用缓存，更新/删除操作后要失效相关缓存
   - 使用 `CacheInvalidator` 统一管理

3. **审计日志**：
   - 重要操作要记录审计日志
   - 在服务层记录，而不是endpoint

4. **性能优化**：
   - 使用关联预加载避免N+1查询
   - 使用查询构建器的 `load_relations` 参数

5. **向后兼容**：
   - 保持API接口不变
   - 只改变内部实现
