# 定时任务队列管理说明

## 问题背景

当多个定时任务在同一时间触发时（例如都是每10分钟执行一次），它们会在同一个进程中并发执行，可能导致：

1. **资源竞争**：数据库连接、内存等资源被多个任务同时占用
2. **性能问题**：多个任务同时执行会影响系统性能
3. **影响其他请求**：占用过多资源可能影响API请求的处理

## 解决方案

实现了**任务执行队列管理器**，用于限制同一进程同时执行的任务数量。

### 核心功能

1. **智能并发控制**：默认允许2个任务并发执行，充分利用进程资源
2. **有空闲即执行**：如果有空闲槽位，任务会立即并发执行，无需排队
3. **自动排队**：只有当达到最大并发数时，新任务才会进入队列等待
4. **优先级支持**：支持任务优先级（CRITICAL > HIGH > NORMAL > LOW）
5. **自动调度**：任务执行完成后自动从队列中取出下一个任务执行

## 配置说明

### 环境变量

在 `.env` 文件中添加以下配置：

```bash
# 最大并发定时任务数（同一进程同时执行的任务数量）
# 默认值：2（允许2个任务并发执行，充分利用进程资源）
# 建议值：
#   - 1：严格顺序执行，适合资源紧张或任务相互依赖的场景
#   - 2-3：推荐值，充分利用进程资源，适合大多数场景
#   - 4+：仅当任务执行时间很短且系统资源充足时使用
MAX_CONCURRENT_SCHEDULED_TASKS=2
```

### 配置建议

- **默认值（2）**：推荐值，允许2个任务并发执行，充分利用进程资源
- **1**：严格顺序执行，适合资源紧张或任务相互依赖的场景
- **3-4**：如果任务执行时间很短（<1分钟），且系统资源充足，可以适当增加
- **不建议超过5**：过多的并发任务可能导致资源耗尽

### 工作原理

任务队列采用**智能并发控制**机制：

1. **有空闲槽位时立即执行**：如果当前运行的任务数 < 最大并发数，新任务会立即执行，不会排队
2. **达到上限时自动排队**：只有当达到最大并发数时，新任务才会进入队列等待
3. **自动调度**：任务执行完成后，自动从队列中取出下一个任务执行

**示例**：
- 最大并发数 = 2
- 任务A触发 → 立即执行（当前运行：1/2）
- 任务B触发 → 立即执行（当前运行：2/2）
- 任务C触发 → 进入队列等待（当前运行：2/2，队列：1）
- 任务A完成 → 任务C从队列取出执行（当前运行：2/2）

## 工作原理

### 执行流程

1. **任务提交**：定时任务触发时，调用 `execute_task_with_lock()`
2. **队列管理**：任务被提交到任务队列管理器
3. **智能并发检查**：
   - **有空闲槽位**：如果 `当前运行任务数 < 最大并发数`，任务**立即并发执行**，无需排队
   - **达到上限**：如果 `当前运行任务数 >= 最大并发数`，任务进入队列等待
4. **自动调度**：任务执行完成后，自动从队列中取出下一个任务执行

### 并发执行示例

假设 `MAX_CONCURRENT_SCHEDULED_TASKS=2`：

```
时间线：
10:00:00 - 任务A触发 → 立即执行（当前运行：1/2）
10:00:01 - 任务B触发 → 立即执行（当前运行：2/2，与任务A并发）
10:00:02 - 任务C触发 → 进入队列等待（当前运行：2/2，队列：1）
10:00:30 - 任务A完成 → 任务C从队列取出执行（当前运行：2/2）
10:00:35 - 任务B完成 → 当前运行：1/2
10:00:40 - 任务C完成 → 当前运行：0/2
```

**关键点**：
- 任务A和B在10:00:01时**并发执行**（充分利用进程资源）
- 任务C在有空闲槽位时**立即执行**，不会一直等待

### 优先级规则

- **CRITICAL（0）**：最高优先级，优先执行
- **HIGH（1）**：高优先级
- **NORMAL（2）**：普通优先级（默认）
- **LOW（3）**：低优先级

相同优先级的任务按提交时间排序（先提交的先执行）。

## 使用示例

### 当前实现

所有定时任务默认使用 `NORMAL` 优先级，通过队列管理执行。

### 自定义优先级（可选）

如果需要为特定任务设置优先级，可以修改 `scheduler.py` 中的 `execute_task_with_lock()` 函数：

```python
# 根据任务名称确定优先级
if task_name == "关键数据同步任务":
    priority = TaskPriority.CRITICAL
elif task_name == "数据归档任务":
    priority = TaskPriority.LOW
else:
    priority = TaskPriority.NORMAL
```

## 监控和日志

### 日志输出

任务队列会记录以下日志：

- **立即执行**：`任务 'xxx' 立即执行（当前运行: 1/1）`
- **加入队列**：`任务 'xxx' 已加入队列等待执行（队列长度: 2, 当前运行: 1/1）`
- **从队列取出**：`任务 'xxx' 从队列中取出执行（等待时间: 5.23秒, 当前运行: 1/1）`

### 队列状态监控

#### API 端点

通过以下 API 端点可以实时查看任务队列状态：

```
GET /api/v1/scheduled-tasks/queue-status
```

**权限要求**：管理员

**返回数据**：
```json
{
  "success": true,
  "message": "获取队列状态成功",
  "data": {
    "current_running": 1,
    "max_concurrent": 1,
    "queue_length": 2,
    "running_tasks": ["TQT API获取数据"],
    "queued_tasks": ["Skymobi API获取数据", "数据归档任务"],
    "queue_details": [
      {
        "task_name": "Skymobi API获取数据",
        "priority": "NORMAL",
        "priority_value": 2,
        "wait_time_seconds": 5.23,
        "submitted_at": "2024-01-01T10:00:00+00:00"
      }
    ]
  }
}
```

#### 程序调用

也可以通过代码获取队列状态：

```python
from app.scheduler_module.task_queue import get_task_queue

queue = get_task_queue()
status = await queue.get_queue_status()
```

## 注意事项

1. **多进程环境**：任务队列是进程级别的，每个进程有独立的队列
2. **数据库锁**：任务队列管理同一进程内的并发，数据库锁确保多进程环境下只执行一次
3. **任务超时**：如果任务执行时间过长，可能会影响队列中其他任务的执行
4. **配置调整**：根据实际任务执行时间和系统资源情况调整 `MAX_CONCURRENT_SCHEDULED_TASKS`

## 最佳实践

1. **默认配置**：使用默认值（1）即可满足大多数场景
2. **错开执行时间**：如果可能，尽量让不同任务的执行时间错开（例如：任务1在0分执行，任务2在5分执行）
3. **监控队列**：定期检查日志，如果队列经常有任务等待，考虑：
   - 增加 `MAX_CONCURRENT_SCHEDULED_TASKS`
   - 优化任务执行时间
   - 错开任务执行时间
4. **优先级使用**：只在必要时使用优先级，避免过度依赖优先级导致低优先级任务长期等待
