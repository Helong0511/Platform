# 扣价后支付金额详细说明

## 一、什么是"扣价"？

**扣价**（也称为"扣量"或"扣减"）是CPL系统中用于控制成本和利润的核心机制。当系统接收到转化回调时，会对原始金额进行扣减，得到最终支付给渠道的金额。

### 1.1 扣价的目的

1. **成本控制**：减少支付给渠道的金额，提高利润空间
2. **风险控制**：过滤低质量转化，降低风险
3. **差异化定价**：不同渠道可以设置不同的扣价比例或固定金额

### 1.2 扣价的类型

系统支持两种扣价方式：

#### 方式1：按比例扣减（百分比扣减）

**计算公式：**
```
扣减金额 = 原始金额 × (扣减比例 / 100)
扣价后金额 = 原始金额 - 扣减金额
```

**示例：**
- 原始金额：`2.80`
- 扣减比例：`20%`
- 扣减金额：`2.80 × 20% = 0.56`
- 扣价后金额：`2.80 - 0.56 = 2.24`

#### 方式2：按固定金额扣减

**计算公式：**
```
扣价后金额 = 原始金额 - 固定扣减金额
```

**示例：**
- 原始金额：`2.80`
- 固定扣减金额：`0.50`
- 扣价后金额：`2.80 - 0.50 = 2.30`

## 二、"扣价后支付金额"的含义

### 2.1 定义

**扣价后支付金额**（`affiliate_payout`）是指在渠道配置中为每个渠道设置的**固定支付金额**，这是最终支付给渠道的实际金额。

### 2.2 关键特点

1. **固定金额**：不随转化金额变化，是预先配置的固定值
2. **渠道级别**：每个渠道可以设置不同的金额
3. **Offer级别**：同一个渠道在不同Offer上可以设置不同的金额
4. **优先级最高**：如果配置了 `affiliate_payout`，优先使用此金额，而不是系统计算的扣减后金额

### 2.3 与系统扣减金额的区别

| 类型 | 字段 | 计算方式 | 是否可变 | 用途 |
|------|------|----------|----------|------|
| **系统扣减后金额** | `conversion.payout` | 根据扣减配置动态计算 | ✅ 可变（随转化金额变化） | 系统内部统计和计算 |
| **渠道配置固定金额** | `affiliate_payout` | 手动配置的固定值 | ❌ 固定（不随转化金额变化） | 实际支付给渠道的金额 |

## 三、业务流程中的位置

### 3.1 完整流程

```
1. 接收转化回调
   ↓
   原始金额（original_payout）：2.80
   
2. 应用系统扣减逻辑
   ↓
   扣减比例：20%
   扣减金额：0.56
   系统扣减后金额（conversion.payout）：2.24
   
3. 查找渠道配置
   ↓
   查找 offer_publisher_assignments 表
   获取 affiliate_payout（如果配置了）
   
4. 确定最终支付金额
   ↓
   如果配置了 affiliate_payout：
      → 使用 affiliate_payout（例如：0.10）
   如果未配置 affiliate_payout：
      → 使用 conversion.payout（例如：2.24）
   
5. 转发给渠道
   ↓
   转发数据：{"payout": 0.10} 或 {"payout": 2.24}
```

### 3.2 具体示例

#### 场景1：配置了固定金额

**配置：**
- Offer ID: `11`
- 渠道ID: `4`
- 下游PO（affiliate_payout）: `0.10`

**转化处理：**
1. 接收转化：原始金额 `2.80`
2. 系统扣减：扣减后金额 `2.24`（扣减20%）
3. 查找配置：找到 `affiliate_payout = 0.10`
4. **最终支付金额：`0.10`**（使用配置的固定金额）
5. 转发给渠道：`{"payout": 0.10}`

#### 场景2：未配置固定金额

**配置：**
- Offer ID: `11`
- 渠道ID: `4`
- 下游PO（affiliate_payout）: `NULL`（未配置）

**转化处理：**
1. 接收转化：原始金额 `2.80`
2. 系统扣减：扣减后金额 `2.24`（扣减20%）
3. 查找配置：未找到 `affiliate_payout`
4. **最终支付金额：`2.24`**（使用系统计算的扣减后金额）
5. 转发给渠道：`{"payout": 2.24}`

## 四、金额字段对比

### 4.1 数据库字段

| 字段 | 表 | 含义 | 示例值 |
|------|-----|------|--------|
| `original_payout` | `postback_conversions` | 转化回调的原始金额 | `2.80` |
| `payout` | `postback_conversions` | 系统扣减后的金额 | `2.24` |
| `affiliate_payout` | `offer_publisher_assignments` | 渠道配置的固定金额 | `0.10` |

### 4.2 金额流转过程

```
转化回调
  ↓
original_payout = 2.80（原始金额）
  ↓
应用扣减逻辑
  ↓
payout = 2.24（系统扣减后金额）
  ↓
查找渠道配置
  ↓
affiliate_payout = 0.10（如果配置了）
  ↓
最终支付金额 = affiliate_payout 或 payout
  ↓
转发给渠道：{"payout": 0.10} 或 {"payout": 2.24}
```

## 五、使用场景

### 5.1 场景1：差异化定价

**需求：** 不同渠道需要不同的支付金额

**配置：**
- 渠道A：`affiliate_payout = 2.00`
- 渠道B：`affiliate_payout = 1.50`
- 渠道C：`affiliate_payout = 0.10`

**效果：**
- 无论转化金额是多少，渠道A总是收到 `2.00`
- 无论转化金额是多少，渠道B总是收到 `1.50`
- 无论转化金额是多少，渠道C总是收到 `0.10`

### 5.2 场景2：固定成本控制

**需求：** 希望将支付给渠道的金额固定在一个较低的水平

**配置：**
- 所有渠道：`affiliate_payout = 0.10`

**效果：**
- 即使转化金额是 `10.00`，也只支付 `0.10`
- 即使转化金额是 `0.50`，也支付 `0.10`（不会低于配置值）

### 5.3 场景3：使用系统扣减金额

**需求：** 希望根据转化金额动态计算支付金额

**配置：**
- 不配置 `affiliate_payout`（设置为 `NULL`）

**效果：**
- 系统会根据扣减配置计算支付金额
- 转化金额 `2.80` → 支付 `2.24`（扣减20%）
- 转化金额 `5.00` → 支付 `4.00`（扣减20%）

**表名：** `offer_publisher_assignments`

**字段：** `affiliate_payout`

**SQL示例：**
```sql

UPDATE offer_publisher_assignments
SET affiliate_payout = 0.10
WHERE offer_id = 11 AND publisher_id = 4;
```

## 八、常见问题

### 8.1 Q: 如果配置了 `affiliate_payout`，系统还会计算扣减吗？

**A:** 是的，系统仍然会计算扣减，但最终支付金额会使用 `affiliate_payout`。

**流程：**
1. 系统计算扣减：`2.80 → 2.24`（扣减20%）
2. 保存到数据库：`conversion.payout = 2.24`
3. 查找渠道配置：`affiliate_payout = 0.10`
4. 转发给渠道：使用 `0.10`（而不是 `2.24`）

### 8.2 Q: `affiliate_payout` 和 `conversion.payout` 有什么区别？

**A:** 
- `conversion.payout`：系统根据扣减配置动态计算的金额，会随转化金额变化
- `affiliate_payout`：手动配置的固定金额，不随转化金额变化

### 8.3 Q: 如果 `affiliate_payout` 设置为 `0`，会支付 `0` 吗？

**A:** 是的，如果设置为 `0`，会支付 `0`。但建议设置为 `NULL`（不配置），这样会使用系统计算的扣减后金额。

### 8.4 Q: 可以为同一个渠道在不同Offer上设置不同的 `affiliate_payout` 吗？

**A:** 是的，`affiliate_payout` 是存储在 `offer_publisher_assignments` 表中的，每个 `(offer_id, publisher_id)` 组合可以有不同的值。

## 九、总结

### 9.1 核心概念

1. **扣价**：对原始金额进行扣减，得到最终支付金额
2. **扣价后支付金额**：渠道配置中的固定金额，是最终支付给渠道的实际金额
3. **优先级**：如果配置了 `affiliate_payout`，优先使用固定金额；否则使用系统计算的扣减后金额

### 9.2 业务价值

1. **差异化定价**：不同渠道可以设置不同的支付金额
2. **成本控制**：可以将支付金额固定在一个较低的水平
3. **灵活性**：可以选择使用固定金额或动态计算的金额

### 9.3 配置建议

1. **需要差异化定价**：为每个渠道配置不同的 `affiliate_payout`
2. **需要固定成本**：为所有渠道配置相同的 `affiliate_payout`
3. **需要动态计算**：不配置 `affiliate_payout`，使用系统计算的扣减后金额
