# 日志权限问题修复指南

## 问题描述

应用启动时出现以下错误：
```
PermissionError: [Errno 13] Permission denied: '/data/Platform/logs/app.log'
```

这是因为应用无法在 `/data/Platform/logs/` 目录创建或写入日志文件。

---

## 解决方案

### 方案1：设置正确的目录权限（推荐）

在服务器上执行以下命令：

```bash
# 1. 确保日志目录存在
sudo mkdir -p /data/Platform/logs

# 2. 设置目录所有者为运行服务的用户（通常是 www-data 或当前用户）
# 如果使用 systemd 服务，检查服务配置中的 User 字段
sudo chown -R www-data:www-data /data/Platform/logs

# 或者如果服务以当前用户运行：
sudo chown -R $USER:$USER /data/Platform/logs

# 3. 设置目录权限（755 = 所有者可读写执行，组和其他用户可读执行）
sudo chmod 755 /data/Platform/logs

# 4. 如果日志文件已存在，也需要设置权限
sudo chown www-data:www-data /data/Platform/logs/app.log 2>/dev/null || true
sudo chmod 644 /data/Platform/logs/app.log 2>/dev/null || true
```

### 方案2：检查 systemd 服务配置

检查 systemd 服务文件中的用户配置：

```bash
# 查看服务配置
sudo systemctl cat Platform-backend.service
```

确保服务配置中包含：

```ini
[Service]
User=www-data  # 或运行服务的用户
Group=www-data
WorkingDirectory=/data/Platform
ReadWritePaths=/data/Platform/logs
```

如果使用 `ReadWritePaths`，确保 systemd 版本 >= 240（Ubuntu 20.04+）。

### 方案3：使用 ExecStartPre 创建目录

在 systemd 服务文件中添加：

```ini
[Service]
ExecStartPre=/bin/mkdir -p /data/Platform/logs
ExecStartPre=/bin/chown -R www-data:www-data /data/Platform/logs
ExecStartPre=/bin/chmod 755 /data/Platform/logs
```

## 完整修复步骤

### 步骤1：检查当前权限

```bash

ls -la /data/Platform/ | grep logs
```


确保包含：

```ini
[Service]

Group=www-data

ExecStartPre=/bin/mkdir -p /data/Platform/logs

ExecStartPre=/bin/chmod 755 /data/Platform/logs
```

### 步骤4：重新加载并重启服务

```bash

sudo systemctl daemon-reload

sudo systemctl restart Platform-backend.service

# 检查服务状态
sudo systemctl status Platform-backend.service

# 查看日志
sudo journalctl -u Platform-backend.service -f
```

## 常见问题

### Q1: 为什么需要 www-data 用户？

A: 如果 systemd 服务配置为以 `www-data` 用户运行，那么该用户需要拥有日志目录的写入权限。

### Q2: 如何查看服务运行的用户？

```bash
# 查看服务配置
sudo systemctl show Platform-backend.service | grep User
```

### Q3: 可以使用其他用户吗？

A: 可以，只需将命令中的 `www-data` 替换为实际运行服务的用户。

### Q4: 权限设置后仍然失败？

A: 检查 SELinux 或 AppArmor 是否阻止了访问：

```bash
# 检查 SELinux（如果启用）
getenforce

# 检查 AppArmor
sudo aa-status | grep platform
```
