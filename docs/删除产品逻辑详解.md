# 删除产品逻辑详解

## 📋 概述

删除产品是一个复杂的操作，涉及多个数据表的关联处理。本文档详细说明删除一个客户的产品时的所有逻辑、数据流转和注意事项。

---

## 🔍 一、删除产品前的检查流程

### 1.1 产品存在性检查

```python
# 位置：app/api/api_v1/endpoints/products.py:786-793
result = await db.execute(select(Product).where(Product.id == product_id))
product = result.scalars().first()

if not product:
    raise_api_exception(
        ErrorCode.PRODUCT_NOT_FOUND,
        detail=f"产品ID {product_id} 不存在"
    )
```

**检查项**：
- ✅ 产品ID是否存在
- ✅ 产品是否已被删除

**失败处理**：返回 404 错误

---

### 1.2 权限检查

```python
# 位置：app/api/api_v1/endpoints/products.py:795-808
if current_user.role != UserRole.ADMIN:
    # 客户只能删除自己的产品
    client_query = select(Client).where(
        Client.id == product.client_id,
        Client.user_id == current_user.id
    )
    client_result = await db.execute(client_query)
    client = client_result.scalars().first()
    if not client:
        raise_api_exception(
            ErrorCode.PRODUCT_NO_PERMISSION,
            detail=f"您没有权限删除产品ID {product_id}，该产品不属于您的客户账户"
        )
```

**权限规则**：
- **管理员（ADMIN）**：可以删除任何产品
- **客户（CLIENT）**：只能删除自己客户账户下的产品

**检查逻辑**：
1. 如果当前用户是管理员 → 跳过权限检查
2. 如果当前用户是客户 → 检查产品的 `client_id` 是否关联到当前用户的客户账户

**失败处理**：返回 403 权限错误

---

### 1.3 关联数据检查

```python
# 位置：app/api/api_v1/endpoints/products.py:814-818
count_result = await db.execute(
    select(func.count(AdData.id)).where(AdData.product_id == product_id)
)
ad_data_count = count_result.scalar() or 0
```

**检查项**：
- ✅ 统计产品关联的广告数据条数（`ad_data` 表）

**检查目的**：决定删除策略
- 如果 `ad_data_count > 0` → **转移策略**（不删除产品，转移到管理员默认客户）
- 如果 `ad_data_count == 0` → **删除策略**（直接删除产品）

---

## 🔄 二、删除策略分支

### 2.1 分支A：有关联广告数据 → 转移策略

**触发条件**：`ad_data_count > 0`

**策略说明**：为了保护历史广告数据，不删除产品，而是将产品转移到管理员的默认客户。

#### 2.1.1 查找或创建管理员默认客户

```python
# 位置：app/api/api_v1/endpoints/products.py:827-860
# 1. 确定管理员用户
admin_user = current_user
if current_user.role != UserRole.ADMIN:
    # 如果不是管理员操作，查找第一个管理员用户
    admin_users_query = select(User).where(User.role == UserRole.ADMIN).limit(1)
    admin_users_result = await db.execute(admin_users_query)
    admin_user = admin_users_result.scalars().first()
    if not admin_user:
        raise_api_exception(
            ErrorCode.NO_ADMIN_USERS,
            detail="系统中没有管理员用户，无法转移产品。请先创建管理员用户"
        )

# 2. 查找管理员的默认客户
admin_client_query = select(Client).where(
    Client.user_id == admin_user.id,
    Client.company_name == "默认客户（导入数据）"
).limit(1)
admin_client_result = await db.execute(admin_client_query)
admin_default_client = admin_client_result.scalars().first()

# 3. 如果不存在，创建管理员的默认客户
if not admin_default_client:
    admin_default_client = Client(
        user_id=admin_user.id,
        company_name="默认客户（导入数据）",
        is_active=True
    )
    db.add(admin_default_client)
    await db.flush()  # 刷新以获取客户ID
    await db.refresh(admin_default_client)
```

**逻辑说明**：
1. **确定管理员用户**：
   - 如果当前用户是管理员 → 使用当前用户
   - 如果当前用户是客户 → 查找第一个管理员用户

2. **查找默认客户**：
   - 查找公司名称为 `"默认客户（导入数据）"` 的客户
   - 必须关联到管理员用户

3. **创建默认客户**（如果不存在）：
   - 自动创建默认客户
   - 关联到管理员用户
   - 设置为激活状态

#### 2.1.2 检查同名产品冲突

```python
# 位置：app/api/api_v1/endpoints/products.py:862-880
existing_product_query = select(Product).where(
    Product.client_id == admin_default_client.id,
    Product.name == product.name,
    Product.id != product_id  # 排除当前产品
)
existing_product_result = await db.execute(existing_product_query)
existing_product = existing_product_result.scalars().first()

if existing_product:
    # 如果管理员的默认客户已有同名产品，仍然转移
    product.client_id = admin_default_client.id
    product.ecpm_deduct_ratio = 0.0
    product.revenue_deduct_ratio = 0.0
else:
    # 正常转移
    old_client_id = product.client_id
    product.client_id = admin_default_client.id
    product.ecpm_deduct_ratio = 0.0
    product.revenue_deduct_ratio = 0.0
```

**处理逻辑**：
- 检查管理员的默认客户是否已有同名产品
- **即使有同名产品，仍然转移**（覆盖同名产品的情况）
- 将产品的减扣比例重置为 0.0

#### 2.1.3 执行产品转移

```python
# 位置：app/api/api_v1/endpoints/products.py:893-919
try:
    await db.commit()
    await db.refresh(product)
    
    # 记录更新操作（产品转移）
    await log_update(
        db=db,
        user=current_user,
        resource_type="PRODUCT",
        resource_id=product_id,
        resource_name=product.name,
        request=request,
        details={
            "action": "transfer_to_admin_default_client",
            "old_client_id": old_client_id,
            "new_client_id": admin_default_client.id,
            "ad_data_count": ad_data_count
        }
    )
    
    return ResponseBaseSchema.success(data={
        "message": f"产品已转移到管理员的默认客户（该产品关联了 {ad_data_count} 条广告数据）",
        "transferred": True,
        "new_client_id": admin_default_client.id
    })
except Exception as e:
    await db.rollback()
    raise_api_exception(...)
```

**执行步骤**：
1. 提交数据库事务（保存产品转移）
2. 刷新产品对象（获取最新数据）
3. 记录审计日志（`log_update`）
4. 返回成功响应

**返回信息**：
- `transferred: true` - 标识为转移操作
- `new_client_id` - 新客户ID（管理员默认客户）
- `message` - 提示信息

---

### 2.2 分支B：无关联广告数据 → 删除策略

**触发条件**：`ad_data_count == 0`

**策略说明**：直接删除产品，因为没有任何历史数据需要保护。

#### 2.2.1 执行产品删除

```python
# 位置：app/api/api_v1/endpoints/products.py:931-951
try:

    await db.delete(product)

    return ResponseBaseSchema.success(data={"message": "产品已成功删除"})
except Exception as e:
    await db.rollback()
    raise_api_exception(...)
```

**执行步骤**：
1. 删除产品（`await db.delete(product)`）
2. 提交数据库事务
3. 记录审计日志（`log_delete`）
4. 返回成功响应

**级联删除**：
- ✅ `product_assignments` 表记录会自动删除（外键 `ON DELETE CASCADE`）
- ✅ 其他关联数据（如果有）也会级联删除

## 📊 三、关联数据表处理

### 3.1 广告数据表（ad_data）

**外键约束**：
```sql
CONSTRAINT `fk_ad_product` FOREIGN KEY (`product_id`) 
    REFERENCES `products`(`id`) ON DELETE RESTRICT ON UPDATE RESTRICT
```

**处理方式**：
- **RESTRICT 约束**：如果产品有关联广告数据，**不允许删除产品**
- **转移策略**：将产品转移到管理员默认客户，保留广告数据关联

**影响**：
- ✅ 广告数据不会被删除
- ✅ 广告数据的 `product_id` 保持不变
- ✅ 产品转移到管理员默认客户后，广告数据仍然可以正常查询

---

### 3.2 产品分配历史表（product_assignments）

**外键约束**：
```sql
CONSTRAINT `fk_pa_product` FOREIGN KEY (`product_id`) 
    REFERENCES `products`(`id`) ON DELETE CASCADE ON UPDATE RESTRICT
```

**处理方式**：
- **CASCADE 约束**：删除产品时，**自动删除所有关联的分配历史记录**

**影响**：
- ✅ 如果产品被删除（无广告数据），分配历史记录会自动删除
- ⚠️ 如果产品被转移（有广告数据），分配历史记录**不会自动更新**
  - 需要手动更新分配历史（当前代码中**未实现**）

**⚠️ 潜在问题**：
- 产品转移后，分配历史记录仍然指向旧客户
- 需要调用 `transfer_product_assignment()` 函数更新分配历史
- **建议**：在转移产品时，同步更新分配历史

---

### 3.3 产品变更历史表（product_change_history，新增）

**外键约束**：
```sql
CONSTRAINT `fk_pch_product` FOREIGN KEY (`product_id`) 
    REFERENCES `products`(`id`) ON DELETE CASCADE ON UPDATE RESTRICT
```

**处理方式**：
- **CASCADE 约束**：删除产品时，**自动删除所有变更历史记录**

**影响**：
- ✅ 如果产品被删除，变更历史记录会自动删除
- ⚠️ 如果产品被转移，变更历史记录**会保留**（因为产品未删除）

**建议**：
- 在删除/转移产品时，记录一条变更历史：
  - 删除：`change_type = "DELETE"`
  - 转移：`change_type = "TRANSFER"`


```
    │   │   │   └─→ 无管理员 → 返回错误

    │   │   ├─→ 检查同名产品冲突
```

## ⚠️ 六、潜在问题和改进建议

### 6.1 问题1：产品转移时未更新分配历史

**问题描述**：
- 产品转移后，`product_assignments` 表中的记录仍然指向旧客户
- 这会导致历史数据查询时，可能无法正确识别产品归属

**影响**：
- 查询历史广告数据时，可能无法正确关联客户
- 产品分配历史时间线不准确

**解决方案**：
```python
# 在转移产品时，同步更新分配历史
if ad_data_count > 0:
    # ... 转移产品逻辑 ...
    
    # 新增：更新产品分配历史
    try:
        await transfer_product_assignment(
            db=db,
            product_id=product.id,
            old_client_id=old_client_id,
            new_client_id=admin_default_client.id,
            transfer_date=date.today()  # 使用当前日期作为转移日期
        )
        logger.info(f"产品 {product.id} 的分配历史已更新")
    except Exception as e:
        logger.error(f"更新产品分配历史失败: {str(e)}", exc_info=True)
        # 分配历史更新失败不影响产品转移，继续执行
```

---

### 6.2 问题2：未记录变更历史

**问题描述**：
- 删除/转移产品时，未在 `product_change_history` 表中记录变更
- 无法追溯产品的删除/转移历史

**解决方案**：
```python
# 在删除/转移产品时，记录变更历史
if ad_data_count > 0:
    # 转移产品
    # ...
    
    # 新增：记录变更历史
    await record_product_change(
        db=db,
        product_id=product.id,
        user=current_user,
        change_type="TRANSFER",
        field_changes={
            "client_id": {
                "old": old_client_id,
                "new": admin_default_client.id
            },
            "ecpm_deduct_ratio": {
                "old": product.ecpm_deduct_ratio,
                "new": 0.0
            },
            "revenue_deduct_ratio": {
                "old": product.revenue_deduct_ratio,
                "new": 0.0
            }
        },
        change_reason=f"删除产品时转移（关联 {ad_data_count} 条广告数据）",
        request=request
    )
else:
    # 删除产品
    # ...
    
    # 新增：记录变更历史（在删除前）
    await record_product_change(
        db=db,
        product_id=product_id,
        user=current_user,
        change_type="DELETE",
        field_changes={
            "deleted": {
                "old": False,
                "new": True
            }
        },
        change_reason="删除产品（无关联广告数据）",
        request=request
    )
```

---

### 6.3 问题3：同名产品冲突处理

**问题描述**：
- 如果管理员的默认客户已有同名产品，仍然转移当前产品
- 这会导致管理员默认客户有多个同名产品

**影响**：
- 产品名称不唯一
- 可能造成数据混淆

**解决方案**：
```python
if existing_product:
    # 方案1：合并产品（将广告数据转移到现有产品）
    # 方案2：重命名产品（添加后缀，如 "产品名_已转移_20250101"）
    # 方案3：拒绝转移，提示用户先删除或重命名现有产品
    
    # 当前实现：仍然转移（可能不是最佳方案）
    product.name = f"{product.name}_已转移_{date.today().strftime('%Y%m%d')}"
    logger.warning(f"产品名称冲突，已重命名为: {product.name}")
```

## 📋 七、数据一致性检查清单

删除产品后，需要验证以下数据的一致性：

- [ ] **产品表（products）**
  - 如果转移：产品 `client_id` 已更新为管理员默认客户ID
  - 如果删除：产品记录已从表中删除

- [ ] **广告数据表（ad_data）**
  - 所有广告数据的 `product_id` 仍然有效（未删除）
  - 如果转移：广告数据仍然关联到产品（产品ID未变）

- [ ] **产品分配历史表（product_assignments）**
  - 如果删除：所有分配历史记录已级联删除
  - 如果转移：分配历史记录已更新（需要手动更新）

- [ ] **产品变更历史表（product_change_history）**
  - 如果删除：所有变更历史记录已级联删除
  - 如果转移：已记录转移变更历史（需要新增）

- [ ] **审计日志表（user_audit_logs）**
  - 已记录删除/转移操作日志
  - 日志包含完整的操作详情

## 🎯 八、总结

### 8.1 删除产品的核心逻辑

1. **权限检查**：确保用户有权限删除产品
2. **关联数据检查**：统计广告数据条数
3. **删除策略选择**：
   - 有广告数据 → 转移策略
   - 无广告数据 → 删除策略
4. **数据一致性**：确保所有关联数据正确处理
5. **审计日志**：记录所有操作

### 8.2 关键点

- ✅ **保护历史数据**：有广告数据时不删除产品
- ✅ **级联删除**：删除产品时自动删除分配历史
- ⚠️ **分配历史更新**：转移产品时需要手动更新分配历史（当前未实现）
- ⚠️ **变更历史记录**：需要新增变更历史记录功能

### 8.3 改进建议

1. **立即改进**：在转移产品时，同步更新产品分配历史
2. **短期改进**：实现变更历史记录功能
3. **长期改进**：优化同名产品冲突处理逻辑
