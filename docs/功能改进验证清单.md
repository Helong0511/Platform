### ✅ 1. CSRF防护验证

- [ ] 检查响应头是否包含 `X-CSRF-Token`

- [ ] 测试CSRF令牌缺失时的错误处理

**验证命令：**
```bash

  -H "Authorization: Bearer YOUR_TOKEN" \
  -v | grep -i "x-csrf-token"

# 测试POST请求（应该包含CSRF令牌）
curl -X POST http://localhost:8960/api/v1/users/ \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "X-CSRF-Token: YOUR_CSRF_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"test","email":"test@example.com","password":"test123456"}'
```

## 常见问题

### 1. 全文索引创建失败

**症状**：SQL执行失败，提示语法错误

**原因**：MySQL版本不支持ngram解析器

**解决**：修改 `scripts/add_fulltext_indexes.sql`，移除 `WITH PARSER ngram` 部分

### 2. Redis连接失败

**症状**：日志显示"Redis连接失败"

**原因**：Redis未启动或配置错误

**解决**：
1. 检查Redis是否运行：`redis-cli ping`
2. 检查环境变量配置
3. 如果不需要Redis，可以不配置（将使用内存存储）

### 3. CSRF令牌验证失败

**症状**：POST请求返回403错误

**原因**：前端未正确发送CSRF令牌

**解决**：
1. 检查前端是否正确处理CSRF令牌
2. 检查浏览器控制台是否有错误
3. 尝试刷新页面重新获取CSRF令牌

### 4. 会话表未创建

**症状**：`Table 'platform.user_sessions' doesn't exist`

**原因**：应用启动时未正确导入模型

**解决**：
1. 检查 `app/models/__init__.py` 是否正确导入所有模型
2. 检查 `app/main.py` 是否正确导入模型
3. 手动执行SQL创建表（参考 `docs/数据库迁移说明.md`）

## 回滚方案

如果出现问题，可以按以下步骤回滚：

1. **禁用CSRF防护**：
   ```env
   ENABLE_CSRF=false
   ```

2. **移除全文索引**：
   ```sql
   ALTER TABLE users DROP INDEX ft_users_search;
   ALTER TABLE clients DROP INDEX ft_clients_search;
   ALTER TABLE products DROP INDEX ft_products_name;
   ALTER TABLE scheduled_tasks DROP INDEX ft_tasks_search;
   ```

3. **删除会话表**（如果需要）：
   ```sql
   DROP TABLE IF EXISTS token_blacklist;
   DROP TABLE IF EXISTS user_sessions;
   ```

4. **恢复代码**：使用Git回滚到之前的版本
