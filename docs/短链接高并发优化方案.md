# 短链接服务高并发优化方案

## 一、优化目标

1. **短链接重定向**：支持高并发访问，响应时间 < 50ms
2. **点击记录存储**：支持每秒数千次点击记录，不阻塞重定向
3. **数据库压力**：减少数据库查询和写入压力

---

## 二、优化方案

### 2.1 Redis队列缓冲（核心优化）

#### 问题
- 每次点击都单独插入数据库，高并发时数据库压力大
- 插入操作可能阻塞重定向响应

#### 解决方案
使用Redis队列缓冲点击记录，定时批量插入到数据库

**架构**：
```
用户点击短链接
    ↓
加入Redis队列（非阻塞，< 1ms）
    ↓
立即重定向（不等待数据库写入）
    ↓
定时任务（每10秒）
    ↓
批量从队列取出（1000条/批）
    ↓
批量插入数据库（bulk insert）
```

**优势**：
- ✅ 重定向不阻塞，响应时间 < 50ms
- ✅ 批量插入提高数据库写入效率（10-100倍）
- ✅ 队列缓冲支持突发流量
- ✅ Redis队列支持高并发（> 10万QPS）

---

### 2.2 Offer信息缓存

#### 问题
- 每次点击都要查询Offer表获取advertiser_id
- 高并发时数据库查询压力大

#### 解决方案
使用Redis缓存Offer的advertiser_id映射

**缓存策略**：
- 缓存键：`offer:cache:{offer_id}`
- 缓存TTL：1小时
- 缓存内容：`{offer_id, advertiser_id, offer_name}`

**工作流程**：
```
需要advertiser_id
    ↓
检查Redis缓存
    ├─ 缓存命中 → 直接使用（< 1ms）✅
    └─ 缓存未命中 → 查询数据库 → 写入缓存
```

**优势**：
- ✅ 减少90%以上的数据库查询
- ✅ 响应时间减少10-50ms
- ✅ 支持高并发访问

---

### 2.3 批量插入优化

#### 问题
- 单条插入效率低
- 数据库连接开销大

#### 解决方案
使用SQLAlchemy的bulk insert批量插入

**批量大小**：
- 每批处理：1000条记录
- 执行频率：每10秒一次
- 最大延迟：10秒（数据最终一致性）

**代码实现**：
```python
# 批量插入（bulk insert）
stmt = insert(Click).values(insert_data)  # 1000条记录
await db.execute(stmt)
await db.commit()
```

**性能提升**：
- 单条插入：~10ms/条
- 批量插入：~100ms/1000条
- **性能提升：100倍**

---

### 2.4 异步补充advertiser_id

#### 问题
- 点击时可能没有advertiser_id（缓存未命中或Offer不存在）
- 需要批量补充

#### 解决方案
在批量处理时统一补充advertiser_id

**流程**：
1. 从队列取出点击记录
2. 收集需要查询的offer_id
3. 批量查询Offer（减少数据库查询）
4. 补充advertiser_id到点击记录
5. 批量插入数据库

**优势**：
- ✅ 批量查询减少数据库压力
- ✅ 使用缓存减少查询次数
- ✅ 不影响重定向响应时间

## 三、代码实现

### 3.1 核心模块

#### 1. Redis队列模块 (`app/core/clicks_queue.py`)
- `enqueue_click()`: 将点击记录加入队列
- `dequeue_clicks()`: 批量从队列取出
- `get_queue_length()`: 获取队列长度

#### 2. Offer缓存模块 (`app/core/offer_cache.py`)
- `get_offer_advertiser_id()`: 从缓存获取advertiser_id
- `set_offer_cache()`: 缓存Offer信息
- `invalidate_offer_cache()`: 清除缓存

#### 3. 批量处理模块 (`app/scheduler/clicks_batch_processor.py`)
- `process_clicks_queue()`: 批量处理队列
- `_enrich_clicks_with_advertiser_id()`: 补充advertiser_id
- `_batch_insert_clicks()`: 批量插入数据库

---

### 3.2 修改的文件

1. **`app/main.py`** - 主路由
   - 使用Redis队列替代后台任务
   - 使用Offer缓存减少数据库查询

2. **`app/api/api_v1/endpoints/short_links.py`** - API路由
   - 使用Redis队列替代后台任务
   - 使用Offer缓存减少数据库查询

3. **`app/scheduler/short_link_tasks.py`** - 定时任务
   - 添加批量处理队列任务

4. **`app/scheduler_module/task_config.py`** - 任务配置
   - 添加"点击记录队列批量处理"任务（每10秒执行）

## 七、降级方案

### 7.1 Redis不可用

如果Redis不可用，自动降级到后台任务：
```python
if not enqueued:
    # 降级到后台任务
    background_tasks.add_task(create_click_background, click_data)
```

### 7.2 队列满

如果队列已满（> 100,000），记录错误日志，降级到后台任务。

---

## 八、数据一致性

### 8.1 最终一致性

- 点击记录可能在队列中等待最多10秒
- 批量处理失败会重试（最多3次）
- 最终保证数据写入数据库

### 8.2 数据丢失风险

- **Redis队列丢失**：如果Redis崩溃，队列中的数据可能丢失
- **缓解措施**：
  - Redis持久化（AOF + RDB）
  - 监控队列长度，及时告警
  - 降级到后台任务作为备份
