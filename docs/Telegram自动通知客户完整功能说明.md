# Telegram 自动通知客户完整功能说明

## 一、功能概述

系统已完整实现 Telegram 自动通知客户的功能，支持实时通知、每小时汇总通知、每天汇总通知，以及高价值转化通知。

## 二、功能特性

### 2.1 通知频率

#### 实时通知（realtime）
- **说明**：转化发生时立即发送通知
- **适用场景**：需要实时了解转化情况的客户
- **优势**：及时性高，信息完整
- **劣势**：转化量大时通知频繁

#### 每小时汇总通知（hourly）
- **说明**：每小时整点汇总并发送一次通知
- **适用场景**：转化量较大，希望减少通知频率的客户
- **优势**：减少通知频率，信息汇总
- **劣势**：有1小时延迟

#### 每天汇总通知（daily）
- **说明**：每天 00:00 汇总并发送一次通知
- **适用场景**：转化量很大，只需要每天统计的客户
- **优势**：通知频率最低，信息高度汇总
- **劣势**：有最多1天延迟

### 2.2 通知类型

#### 普通转化通知
- **触发条件**：转化发生且配置了通知
- **消息内容**：转化详情（产品、平台、转化ID、金额、时间等）

#### 高价值转化通知
- **触发条件**：转化金额超过配置的阈值
- **消息内容**：转化详情 + 阈值信息
- **优势**：只关注高价值转化，减少通知量

#### 汇总通知
- **触发条件**：定时任务执行时
- **消息内容**：汇总统计（转化总数、总金额、时间范围等）
- **优势**：信息汇总，便于统计

## 三、配置说明

### 3.1 客户通知配置

客户需要在系统中配置以下信息：

#### 基本配置
- **启用通知**：打开通知开关
- **通知转化事件**：选择是否通知所有转化
- **高价值转化通知**（可选）：设置阈值，只通知超过阈值的转化

#### 渠道配置
- **通知渠道**：选择 Telegram
- **Telegram Chat ID**：填写客户的 Telegram Chat ID

#### 频率配置
- **通知频率**：选择 realtime/hourly/daily

### 3.2 获取 Telegram Chat ID

#### 方法一：使用 @userinfobot
1. 在 Telegram 中搜索 `@userinfobot`
2. 发送 `/start` 命令
3. 机器人会返回您的 Chat ID

#### 方法二：使用系统提供的链接
1. 在通知配置对话框中
2. 点击"获取 Chat ID"链接
3. 按照提示操作

## 五、使用流程

### 5.1 配置客户通知

1. **登录系统**（管理员）
2. **进入用户管理页面**（侧边栏 → 用户管理）
3. **找到客户用户**（role = 'client'）
4. **点击"通知"按钮**
5. **配置通知设置**：
   - 启用通知：✅
   - 通知转化事件：✅
   - 高价值转化通知（可选）：设置阈值
   - 通知渠道：Telegram ✅
   - Telegram Chat ID：填写客户的 Chat ID
   - 通知频率：选择 realtime/hourly/daily
6. **点击"保存"**

### 5.2 测试通知

1. **触发转化**（通过 Postback API）
2. **检查通知**：
   - 实时通知：立即收到
   - 每小时汇总：等待到下一个整点
   - 每天汇总：等待到第二天 00:00

### 5.3 查看通知记录

1. **进入 Postback 管理页面**
2. **查看转化记录**
3. **点击"通知记录"按钮**
4. **查看通知历史**：
   - 实时通知：显示转化ID
   - 汇总通知：显示"汇总通知"标签

## 六、技术细节

### 6.1 通知触发流程

```
转化发生
  ↓
PostbackProcessor.process()
  ↓
保存转化记录
  ↓
PostbackNotifier.notify_conversion()
  ↓
查询客户通知配置
  ↓
检查是否需要通知
  ↓
根据通知频率处理：
  ├─ realtime → 立即发送 Telegram 通知
  ├─ hourly → 加入 Redis 队列
  └─ daily → 加入 Redis 队列
```

### 6.2 汇总任务流程

```
定时任务执行（每小时/每天）
  ↓
从 Redis 队列获取通知
  ↓
按客户和产品分组
  ↓
构建汇总消息
  ↓
发送汇总通知
  ↓
记录通知历史
```

### 6.3 降级策略

#### Redis 不可用
- **检测**：检查 Redis 连接状态
- **降级**：自动降级为实时发送
- **日志**：记录警告日志

#### 队列满
- **检测**：检查队列长度（最大 10000 条）
- **降级**：自动降级为实时发送
- **日志**：记录警告日志

#### 通知发送失败
- **处理**：不影响主流程
- **记录**：记录错误日志和通知历史（状态为 `failed`）

## 七、性能特性

### 7.1 异步处理

- **实时通知**：使用 `asyncio.create_task()` 异步发送
- **不阻塞**：不影响主流程
- **性能**：高并发场景下性能良好

### 7.2 Redis 队列

- **操作**：使用 `lpush` 和 `rpop`
- **过期时间**：hourly 2小时，daily 2天
- **长度限制**：每个客户队列最大 10000 条

### 7.3 消息长度限制

- **Telegram 限制**：最大 4096 字符
- **处理方式**：自动截断，保留重要信息
- **提示信息**：显示原始消息长度

## 八、监控和告警

### 8.1 建议监控指标

1. **通知发送成功率**
   - 实时通知发送成功率
   - 汇总通知发送成功率
   - 按客户统计发送成功率

2. **定时任务执行**
   - 每小时汇总任务执行时间
   - 每天汇总任务执行时间
   - 任务执行成功率

3. **Redis 队列状态**
   - 队列长度
   - 队列处理速度
   - Redis 连接状态

### 8.2 建议告警规则

1. **通知发送失败率过高**
   - 阈值：失败率 > 10%
   - 告警方式：Telegram 通知管理员

2. **Redis 队列积压**
   - 阈值：队列长度 > 1000
   - 告警方式：Telegram 通知管理员

3. **定时任务执行失败**
   - 阈值：连续失败 3 次
   - 告警方式：Telegram 通知管理员

## 九、常见问题

### 9.1 客户没有收到通知

**可能原因**：
1. Telegram Chat ID 配置错误
2. 通知未启用
3. 通知频率配置错误
4. Telegram Bot 未启动

**解决方法**：
1. 检查客户通知配置
2. 测试 Telegram 连接
3. 检查日志
4. 验证 Telegram Bot 状态

### 9.2 汇总通知没有发送

**可能原因**：
1. Redis 不可用
2. 定时任务未执行
3. 队列为空

**解决方法**：
1. 检查 Redis 连接
2. 检查定时任务执行记录
3. 检查队列内容
4. 检查日志

### 9.3 通知记录查询不到汇总通知

**可能原因**：
1. 数据库迁移未执行
2. `conversion_id` 字段仍为 `NOT NULL`

**解决方法**：
1. 执行数据库迁移脚本
2. 验证字段修改

## 十、最佳实践

### 10.1 通知频率选择

- **转化量小（< 10/小时）**：使用实时通知
- **转化量中等（10-100/小时）**：使用每小时汇总
- **转化量大（> 100/小时）**：使用每天汇总

### 10.2 高价值阈值设置

- **建议**：设置为平均转化金额的 2-3 倍
