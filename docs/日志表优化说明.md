# 日志表优化说明

## 📋 优化内容

### 1. **自动清理旧日志任务**

创建了 `cleanup_old_logs.py` 任务，用于定期清理或归档旧的用户操作日志。

**功能特点**：
- ✅ 自动清理超过保留天数的日志
- ✅ 支持直接删除或归档到归档表
- ✅ 可配置保留天数（默认 90 天）
- ✅ 统计清理结果并记录日志

### 2. **配置参数**

在 `app/core/config.py` 中添加了以下配置：

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|----------|--------|------|
| `AUDIT_LOG_RETENTION_DAYS` | `AUDIT_LOG_RETENTION_DAYS` | 90 | 日志保留天数（天） |
| `AUDIT_LOG_ARCHIVE` | `AUDIT_LOG_ARCHIVE` | false | 是否归档（true/false） |

**配置建议**：
- **高频操作场景**：30-60 天
- **一般场景**：90-180 天（推荐）
- **长期审计需求**：180+ 天

### 3. **任务注册**

已在 `task_registry.py` 中注册清理日志任务，可以通过定时任务系统执行。

## 🚀 使用方法

### 方法 1：通过定时任务系统（推荐）

1. **在数据库中创建定时任务**：

```sql
INSERT INTO `scheduled_tasks` (
    `task_name`, 
    `is_active`, 
    `cron_expression`, 
    `description`, 
    `function_path`
) VALUES (
    '清理旧日志',
    1,
    '0 2 1 * *',  -- 每月1号凌晨2点执行
    '清理90天前的用户操作日志，减少日志表数据量',
    'app.scheduler_module.tasks.cleanup_old_logs.cleanup_old_audit_logs'
);
```

2. **配置环境变量**（可选）：

```bash
# .env 文件
AUDIT_LOG_RETENTION_DAYS=90      # 保留90天
AUDIT_LOG_ARCHIVE=false           # 直接删除，不归档
```

### 方法 2：手动执行

```python
from app.scheduler_module.tasks.cleanup_old_logs import cleanup_old_audit_logs

# 清理90天前的日志（直接删除）
result = await cleanup_old_audit_logs(days=90, archive=False)

# 归档90天前的日志到归档表
result = await cleanup_old_audit_logs(days=90, archive=True)
```

## 📊 执行结果

任务执行后会返回：

```python
{
    "deleted_count": 1000,      # 删除的日志条数
    "archived_count": 0,         # 归档的日志条数（如果启用归档）
    "cutoff_date": "2024-01-01 00:00:00",  # 清理日期阈值
    "message": "删除 1000 条日志"
}
```

## ⚙️ 归档模式

如果启用归档模式（`AUDIT_LOG_ARCHIVE=true`）：

1. **自动创建归档表**：`user_audit_logs_archive`
2. **先归档后删除**：确保数据不丢失
3. **归档表结构**：与主表一致，但只保留必要的索引

**注意**：
- 归档表会占用额外存储空间
- 归档表主要用于历史查询，不参与日常操作
- 建议仅在需要长期保留日志时启用

## 📝 最佳实践

1. **保留天数设置**：
   - 根据业务需求设置合理的保留天数
   - 建议从 90 天开始，根据实际情况调整

2. **执行频率**：
   - 建议每月执行一次（`0 2 1 * *`）
   - 如果日志量很大，可以每周执行（`0 2 * * 0`）

3. **归档 vs 删除**：
   - **直接删除**：适合大多数场景，节省存储空间
   - **归档**：仅在需要长期审计时使用

4. **性能优化**：
   - 清理任务在低峰期执行（如凌晨）
   - 定期检查索引是否有效
   - 如果日志量特别大，考虑分批清理

## 🎯 优化效果

- ✅ **减少存储空间**：定期清理旧日志，控制表大小
- ✅ **提升查询性能**：减少数据量，提升查询速度
- ✅ **自动化管理**：无需手动干预，自动执行
- ✅ **灵活配置**：可根据需求调整保留天数和归档策略

## ⚠️ 注意事项

1. **数据不可恢复**：直接删除的日志无法恢复，请谨慎设置保留天数
2. **归档表维护**：如果启用归档，需要定期清理归档表
3. **执行时间**：大量日志清理可能需要较长时间，建议在低峰期执行
4. **备份建议**：清理前建议备份重要日志数据
