## ⚠️ 风险评估

### 高风险项
- [ ] **数据迁移**：现有产品数据初始化变更历史
  - 缓解：分批执行，添加进度监控
- [ ] **性能影响**：新增索引可能影响写入性能
  - 缓解：在低峰期执行，监控性能指标
- [ ] **兼容性**：新API可能影响现有前端
  - 缓解：保持向后兼容，新功能可选

### 中风险项
- [ ] **变更历史表数据增长**：长期运行数据量大
  - 缓解：定期归档，使用分区表
- [ ] **统计信息准确性**：实时查询 vs 缓存表
  - 缓解：根据数据量选择方案

## 🔄 回滚方案

### 如果实施失败
1. **数据库回滚**
   ```sql
   -- 删除新增表
   DROP TABLE IF EXISTS `product_change_history`;
   
   -- 删除新增索引（需要逐个删除）
   ALTER TABLE `products` DROP INDEX `idx_products_client_active`;
   ALTER TABLE `products` DROP INDEX `idx_products_client_name`;
   ALTER TABLE `products` DROP INDEX `idx_products_covering`;
   ALTER TABLE `ad_data` DROP INDEX `idx_ad_data_product_covering`;
   ALTER TABLE `ad_data` DROP INDEX `idx_ad_data_product_date_range`;
   ```

2. **代码回滚**
   - 使用Git回滚到实施前的版本
   - 重新部署

3. **数据恢复**
   - 从备份恢复数据库
