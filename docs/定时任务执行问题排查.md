# 定时任务执行问题排查指南

## 问题：定时任务没有执行（包括手动触发）

### 已修复的问题

1. **手动触发时跳过进程分配检查**
   - 问题：手动触发任务时，也会检查进程分配，如果任务被分配给其他进程，手动触发会被跳过
   - 修复：手动触发时，添加 `skip_process_check=True` 参数，直接执行任务

2. **增强日志输出**
   - 所有关键步骤都添加了详细的日志输出
   - 包含进程ID、任务名称、执行状态等信息

## 排查步骤

### 1. 检查调度器状态

```bash
GET /api/v1/scheduled-tasks/scheduler-status
```

**检查要点：**
- `scheduler_running` 应为 `true`
- `total_jobs` 应大于 0
- 每个任务应有 `next_run_time`

### 2. 检查任务是否已注册

查看应用启动日志：
```bash
tail -f logs/app.log | grep -i "定时任务\|scheduler"
```

**关键日志：**
- `[Worker PID:xxx] 定时任务初始化完成: 成功注册 X 个任务`
- `[Worker PID:xxx] 定时任务调度器已启动，当前已注册 X 个任务`
- `[Worker PID:xxx] 已注册的任务列表:`

### 3. 检查任务执行日志

```bash
tail -f logs/app.log | grep -i "任务.*开始执行\|任务.*执行完成"
```

**关键日志：**
- `[Worker PID:xxx] 任务 'xxx' 开始执行`
- `[定时任务执行] xxx 开始执行`
- `[定时任务执行] xxx 执行完成`

### 4. 检查进程分配

**单进程环境：**
- 如果只有一个进程，任务应该直接执行
- 日志应显示：`任务 'xxx' 单进程环境或首次运行，分配给当前进程`

**多进程环境：**
- 相同执行时间的任务会被分配到不同进程
- 日志可能显示：`任务 'xxx' 已分配给其他进程执行，当前进程跳过`
- **这是正常的**，任务会在分配的进程中执行

### 5. 检查任务队列状态

```bash
GET /api/v1/scheduled-tasks/queue-status
```

**检查要点：**
- `current_running`: 当前正在执行的任务数
- `max_concurrent`: 最大并发任务数（默认2）
- `queue_length`: 队列中等待的任务数

### 6. 手动触发测试

```bash
POST /api/v1/scheduled-tasks/{task_name}/trigger
```

**修复后：**
- 手动触发会跳过进程分配检查
- 日志应显示：`开始手动触发任务 'xxx'（跳过进程分配检查）`
- 任务应该立即执行

## 常见问题

### 问题1：任务已注册但未执行

**可能原因：**
1. 进程分配问题：任务被分配给其他进程
2. 任务队列已满：`current_running >= max_concurrent`
3. 任务锁被占用：`is_running=True`

**解决方案：**
1. 检查日志，确认任务是否被分配给其他进程
2. 如果是单进程环境，任务应该直接执行
3. 检查任务锁状态：`SELECT * FROM task_locks WHERE task_name='xxx'`

### 问题2：手动触发也没有执行

**已修复：**
- 手动触发现在会跳过进程分配检查
- 直接执行任务，不受进程分配限制

**如果仍然不执行：**
1. 检查任务函数是否存在
2. 检查任务锁是否被占用
3. 查看详细错误日志

### 问题3：多进程环境下任务被跳过

**这是正常的：**
- 相同执行时间的任务会被分配到不同进程
- 日志会显示：`任务 'xxx' 已分配给其他进程执行，当前进程跳过`
- 任务会在分配的进程中执行

**验证方法：**
- 检查所有进程的日志
- 使用 `scheduler-status` API 检查不同进程的任务分配

### 问题4：任务执行时间不准确

**可能原因：**
1. 时区配置错误
2. Cron表达式格式错误
3. 系统时间不准确

**解决方案：**
1. 检查 `TIMEZONE` 配置
2. 验证Cron表达式格式（APScheduler 5字段格式）
3. 检查系统时间

## 调试技巧

### 1. 启用详细日志

在 `.env` 中设置：
```bash
LOG_LEVEL=DEBUG
```

### 2. 检查任务锁状态

```sql
SELECT task_name, is_running, last_run_time, locked_by_pid, locked_by_host
FROM task_locks
WHERE task_name = 'your_task_name';
```

### 3. 检查任务配置

```sql
SELECT task_name, cron_expression, is_active, function_path
FROM scheduled_tasks
WHERE task_name = 'your_task_name';
```

### 4. 查看进程分配

检查日志中的进程分配信息：
```bash
grep "任务.*分配给" logs/app.log
```

## 修复后的改进

1. **手动触发优化**
   - 手动触发时跳过进程分配检查
   - 直接执行任务，不受进程分配限制

2. **日志增强**
   - 所有关键步骤都有详细日志
   - 包含进程ID、任务名称、执行状态

3. **进程分配优化**
   - 单进程环境自动使用当前进程
   - 首次运行自动使用当前进程
   - 详细的分配日志
