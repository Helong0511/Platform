# 登录401错误排查指南

## 问题描述
登录时出现 `401 (Unauthorized)` 错误。

## 已修复的问题
✅ **导入问题已修复**：`app/api/api_v1/endpoints/auth.py` 中已添加缺失的 `datetime` 和 `timezone` 导入。

## 解决步骤

### 1. 重启后端服务（必须）

代码修复后，**必须重启后端服务**才能生效。

#### 方式1：使用 systemd 服务（生产环境）
```bash
sudo systemctl restart Platform-backend
# 检查服务状态
sudo systemctl status Platform-backend
# 查看日志
sudo journalctl -u Platform-backend -n 50 --no-pager
```

#### 方式2：使用 Docker
```bash
docker-compose restart backend
# 或
docker restart platform_backend_dev
# 查看日志
docker logs platform_backend_dev --tail 50
```

#### 方式3：直接运行 uvicorn（开发环境）
1. 停止当前进程（Ctrl+C）
2. 重新启动：
```bash
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8960
```

### 2. 检查浏览器网络请求详情

在浏览器开发者工具中检查登录请求的详细信息：

1. **打开开发者工具**（F12）
2. **切换到 Network（网络）标签**
3. **尝试登录**
4. **点击失败的登录请求**（`/api/v1/auth/login`）
5. **查看以下信息**：

#### Response（响应）标签
- **Status Code**: 应该是 401
- **Response Body**: 查看错误详情，例如：
  ```json
  {
    "detail": "用户名或密码不正确"
  }
  ```
  或
  ```json
  {
    "detail": "登录失败，请稍后重试"
  }
  ```

#### Request（请求）标签
- **Request Headers**: 确认 `Content-Type: application/x-www-form-urlencoded`
- **Request Payload**: 确认包含：
  - `username`: 用户名
  - `password`: 密码
  - `grant_type`: password

### 3. 检查后端日志

后端日志会记录具体的失败原因：

```bash
# systemd 服务
sudo journalctl -u Platform-backend -n 100 --no-pager | grep -i "login\|error\|exception"

# Docker
docker logs platform_backend_dev --tail 100 | grep -i "login\|error\|exception"

# 或查看日志文件
tail -n 100 logs/error.log | grep -i "login\|error\|exception"
```

常见日志信息：
- `用户登录失败: 用户不存在` - 用户名错误
- `用户登录失败: 密码错误` - 密码错误
- `用户登录失败: 用户已被禁用` - 用户被禁用
- `用户登录失败: 登录受限` - 登录被限制
- `登录过程中发生异常` - 代码错误（已修复）

### 4. 验证用户状态

确认登录的用户账户状态：

1. **检查用户是否存在**
   - 确认用户名拼写正确
   - 检查是否有大小写问题

2. **检查用户状态**
   - `is_active` 应为 `True`（用户未被禁用）
   - `login_restricted` 应为 `False`（登录未被限制）

3. **检查密码**
   - 确认密码正确
   - 检查是否有特殊字符编码问题

4. **检查IP白名单**（仅客户用户）
   - 如果用户角色是 `CLIENT`，检查IP是否在白名单中
   - `127.0.0.1` 和 `localhost` 始终允许

### 5. 测试API端点

使用 curl 或 Postman 测试登录API：

```bash
curl -X POST "https://admin.king-sms.com/api/v1/auth/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=your_username&password=your_password&grant_type=password"
```

### 6. 常见问题

#### 问题1：后端服务未重启
**症状**：修复代码后仍然报错
**解决**：重启后端服务

#### 问题2：用户名或密码错误
**症状**：日志显示"用户不存在"或"密码错误"
**解决**：检查用户名和密码

#### 问题3：用户被禁用
**症状**：日志显示"用户已被禁用"，返回403错误
**解决**：在数据库中设置 `is_active = True`

#### 问题4：IP白名单限制
**症状**：日志显示"IP不在白名单中"，返回403错误
**解决**：将当前IP添加到客户的白名单，或清空白名单（允许所有IP）

#### 问题5：数据库连接问题
**症状**：日志显示数据库连接错误
**解决**：检查数据库配置和连接
