# 字符集排序规则冲突修复说明

## 问题描述

在执行包含 `ad_data.country_code` 和 `countries.alpha_2_code` JOIN 操作的查询时，出现以下错误：

```
(pymysql.err.OperationalError) (1267, "Illegal mix of collations (utf8mb4_unicode_ci,IMPLICIT) and (utf8mb4_0900_ai_ci,IMPLICIT) for operation '='")
```

**原因**：
- `ad_data.country_code` 字段使用 `utf8mb4_unicode_ci` 排序规则
- `countries.alpha_2_code` 字段使用 `utf8mb4_0900_ai_ci` 排序规则
- MySQL 不允许不同排序规则的字段直接进行比较

## 解决方案

### 方案1：永久修复（推荐）

运行 SQL 脚本统一表结构排序规则：

```bash
mysql -u your_username -p platform < scripts/fix_collation_issue.sql
```

或者直接在 MySQL 客户端中执行 `scripts/fix_collation_issue.sql` 文件。

**此方案会**：
- 将 `countries` 表的所有相关字段统一为 `utf8mb4_unicode_ci`
- 永久解决排序规则冲突问题
- 不需要修改代码

### 方案2：临时修复（已实施）

已在代码中添加临时修复，使用 `COLLATE` 函数在 JOIN 时强制统一排序规则：

**修改的文件**：
1. `app/api/api_v1/endpoints/ad_data.py` - 添加了 `join_country_info()` 辅助函数，使用列对象的 `collate()` 方法
2. `app/api/api_v1/endpoints/client_api.py` - 修复了 JOIN 语句，使用 `collate()` 方法
3. `app/api/api_v1/endpoints/excel/export_handler.py` - 修复了 JOIN 语句，使用 `collate()` 方法

**修复方法**：
使用 SQLAlchemy 列对象的 `collate()` 方法统一排序规则：
```python
AdData.country_code.collate('utf8mb4_unicode_ci') == 
CountryInfo.alpha_2_code.collate('utf8mb4_unicode_ci')
```

**临时方案特点**：
- ✅ 可以立即解决问题
- ✅ 使用 SQLAlchemy 标准方法，兼容性好
- ⚠️ 每次查询都需要执行 COLLATE 转换，性能略受影响
- ⚠️ 需要修改多处代码

## 推荐操作

1. **立即生效**：代码已修复，可以正常使用
2. **长期方案**：建议运行 `scripts/fix_collation_issue.sql` 统一表结构
3. **验证修复**：运行 SQL 脚本后，可以移除代码中的临时修复（可选）

## 验证修复

运行以下 SQL 查询验证排序规则是否统一：

```sql
SELECT 
    TABLE_NAME,
    COLUMN_NAME,
    CHARACTER_SET_NAME,
    COLLATION_NAME
FROM 
    INFORMATION_SCHEMA.COLUMNS
WHERE 
    TABLE_SCHEMA = 'platform'
    AND TABLE_NAME IN ('ad_data', 'countries')
    AND COLUMN_NAME IN ('country_code', 'alpha_2_code')
ORDER BY 
    TABLE_NAME, COLUMN_NAME;
```

修复后，两个字段的 `COLLATION_NAME` 应该都是 `utf8mb4_unicode_ci`。
