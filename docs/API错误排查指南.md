# API 错误排查指南

## 错误类型说明

### 401 错误（未授权）

**含义**：请求缺少有效的认证信息，或认证信息已过期。

**常见原因**：
1. **Token 过期**：登录 token 已过期，需要重新登录
2. **Token 无效**：token 格式错误或已被撤销
3. **未登录**：用户未登录或登录状态丢失

**解决方法**：
1. **重新登录**：退出并重新登录系统
2. **检查浏览器控制台**：查看是否有认证相关的错误信息
3. **清除浏览器缓存**：清除 cookies 和 localStorage，然后重新登录

**常见端点**：
- `/api/v1/ml-model/timezone` - 需要登录
- `/api/v1/auth/logout` - 需要登录

### 500 错误（服务器内部错误）

**含义**：服务器处理请求时发生了内部错误。

**常见原因**：
1. **代码错误**：后端代码存在 bug
2. **数据库连接问题**：数据库连接失败或查询错误
3. **数据格式问题**：请求数据格式不正确
4. **依赖问题**：缺少必要的 Python 库

**解决方法**：
1. **查看服务器日志**：检查 `logs/app.log` 文件，查找详细的错误信息
2. **检查数据库连接**：确保数据库服务正常运行
3. **检查请求数据**：确保上传的文件格式正确
4. **重启服务**：如果是临时问题，尝试重启后端服务

**常见端点**：
- `/api/v1/ml-model/import` - 导入训练数据
- `/api/v1/users/stats` - 获取用户统计
- `/api/v1/users/` - 获取用户列表

## 具体错误排查

### 1. `/api/v1/ml-model/timezone` - 401 错误

**问题**：获取时区配置时认证失败

**排查步骤**：
1. 检查是否已登录
2. 检查 token 是否有效（查看浏览器 localStorage 或 cookies）
3. 尝试重新登录

**临时解决方案**：
前端代码已经处理了这种情况，如果获取时区失败，会使用默认值 `Asia/Shanghai`。

### 2. `/api/v1/ml-model/import` - 500 错误

**问题**：导入训练数据时服务器错误

**排查步骤**：
1. **查看服务器日志**：
   ```bash
   tail -f logs/app.log | grep "导入训练数据失败"
   ```

2. **检查常见问题**：
   - Excel 文件格式是否正确
   - 文件是否损坏
   - 数据库连接是否正常
   - 是否有必要的 Python 库（xlrd, openpyxl）

3. **检查错误详情**：
   - 查看日志中的堆栈跟踪
   - 查看前端控制台的错误信息

**已修复的问题**：
- ✅ `conflicts` 变量作用域问题
- ✅ 文件对象创建问题
- ✅ 错误处理改进

### 3. `/api/v1/users/stats` - 500 错误

**问题**：获取用户统计信息时服务器错误

2. **检查数据库**：

   - 检查数据库连接配置

3. **检查数据完整性**：

**已修复的问题**：
- ✅ 添加了客户信息查询的错误处理

## 查看日志的方法

### 方法一：查看日志文件

```bash
# 查看最新的错误日志
tail -f logs/app.log | grep ERROR

# 查看特定端点的错误
tail -f logs/app.log | grep "ml-model/import"

# 查看所有 500 错误
tail -f logs/app.log | grep "500"
```

### 方法二：查看 Gunicorn 日志

```bash
# 查看访问日志
tail -f logs/gunicorn_access.log

# 查看错误日志
tail -f logs/gunicorn_error.log
```

### 方法三：查看系统日志（如果使用 systemd）

```bash
# 查看服务日志
sudo journalctl -u Platform-backend -f

# 查看最近的错误
sudo journalctl -u Platform-backend -p err
```

## 常见解决方案

### 1. 401 错误 - 重新登录

如果遇到 401 错误，最简单的方法是：
1. 退出登录
2. 清除浏览器缓存和 cookies
3. 重新登录

### 2. 500 错误 - 检查日志

如果遇到 500 错误：
1. 查看服务器日志获取详细错误信息
2. 根据错误信息修复问题
3. 如果是临时问题，尝试重启服务

### 3. 数据库连接问题

如果怀疑是数据库连接问题：
```bash
# 检查数据库服务状态
sudo systemctl status mysql

# 测试数据库连接
mysql -u root -p -e "SELECT 1"
```

### 4. 依赖问题

如果怀疑是 Python 依赖问题：
```bash
# 检查已安装的包
pip list | grep xlrd
pip list | grep openpyxl

# 重新安装依赖
pip install -r requirements.txt
```

## 预防措施

1. **定期检查日志**：定期查看日志文件，及时发现潜在问题
2. **监控服务状态**：使用监控工具监控服务健康状态
3. **备份数据**：定期备份数据库，防止数据丢失
4. **更新依赖**：定期更新 Python 依赖，修复已知问题
