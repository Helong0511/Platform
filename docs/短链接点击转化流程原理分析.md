## 一、实际案例流程分析

### 1.1 完整流程示例

根据提供的实际案例，完整流程如下：

#### 步骤1：渠道点击短链接
```
原始点击URL：
https://client.btfrx.online/s/kDCT?offer_id=10&channel_id=4&click_id=1230180&sub_channel_id={pub_id}
```

**参数分析：**
- `offer_id=10` - 系统必须参数（Offer ID）
- `channel_id=4` - 系统必须参数（渠道ID）
- `click_id=1230180` - **渠道提供的原始click_id**（可能是数字或字符串格式，由渠道自定义）
- `sub_channel_id={pub_id}` - 渠道参数（包含占位符，会被过滤）

#### 步骤2：系统处理并跳转
```
最终跳转URL：
http://keplerads.fuse-ad.com/tl?a=3058&o=7360&aff_click_id=bpt7KMtEX497DrdtKWMPMweTXEYA4wKkpmbhFjHE&sub_affid=4
```

**关键变化：**
- 系统生成新的click_id：`bpt7KMtEX497DrdtKWMPMweTXEYA4wKkpmbhFjHE`（字符串格式）
- 渠道原始click_id `1230180` 被保存到 `clicks.url_params` 字段
- 跳转URL使用系统生成的click_id

#### 步骤3：转化发生（Postback接收）
```
Postback接收数据：
click_id=bpt7KMtEX497DrdtKWMPMweTXEYA4wKkpmbhFjHE&payout=2.80
```

**说明：**
- 广告主返回的click_id是系统生成的（`bpt7KMtEX497DrdtKWMPMweTXEYA4wKkpmbhFjHE`）
- 原始payout是 `2.80`

#### 步骤4：扣减处理
```
扣减后payout：2.42
```

**说明：**
- 系统应用扣减配置，将payout从 `2.80` 扣减到 `2.42`
- 扣减金额：`2.80 - 2.42 = 0.38`

#### 步骤5：转发给渠道
```
渠道Postback URL配置：
https://www.qqpqq.com/back/p_back?m=tp&c_id={click_id}&payout={payout}

转发执行的URL：
https://www.qqpqq.com/back/p_back?m=tp&c_id=1230180&payout=2.42

转发后返回的json：
{"code":200,"message":"回传信息更新成功","data":{"c_id":1230180,"payout":2.42,"back_time":"2026-01-12T04:06:54.675Z"}}
```

**关键变化：**
- `{click_id}` 占位符被替换为渠道原始click_id：`1230180`（从 `clicks.url_params` 中提取）
- `{payout}` 占位符被替换为扣减后的payout：`2.42`（不是原始的 `2.80`）

## 二、核心原理总结

### 2.1 Click ID 的双重身份机制

系统实现了**Click ID的双重身份机制**：

1. **系统生成的Click ID**（用于内部追踪）
   - 格式：字符串（如 `bpt7KMtEX497DrdtKWMPMweTXEYA4wKkpmbhFjHE`）
   - 用途：
     - 保存到 `clicks.click_id` 字段
     - 用于跳转到广告主
     - 用于接收Postback时匹配转化记录
   - 生成方式：`generate_click_id_from_timestamp()`

2. **渠道原始Click ID**（用于渠道追踪）
   - 格式：**可能是数字或字符串**，由渠道自定义（例如：`1230180`、`abc123`、`wnDYcdbppM3dBkeNAtf4ncebHzEhz8TM` 等）
   - 用途：
     - 保存到 `clicks.url_params` 字段（JSON格式）
     - 转发给渠道时使用
   - 来源：渠道在点击短链接时提供的 `click_id` 参数

### 2.2 数据流转路径

```
渠道点击
  ↓
[系统生成新click_id] ← 用于内部追踪
  ↓
[保存渠道原始click_id到url_params] ← 用于转发给渠道
  ↓
跳转到广告主（使用系统生成的click_id）
  ↓
广告主返回Postback（使用系统生成的click_id）
  ↓
[应用扣减配置] ← 扣减payout
  ↓
转发给渠道（使用渠道原始click_id + 扣减后的payout）
```

### 2.3 Payout 扣减机制

1. **原始Payout（PO）**
   - 来源：广告主Postback返回的payout
   - 示例：`2.80`
   - 保存到：`postback_conversions.original_payout`

2. **扣减后Payout（PO(扣)）**
   - 计算方式：根据扣减配置计算
   - 示例：`2.42`（从 `2.80` 扣减 `0.38`）
   - 保存到：`postback_conversions.payout`
   - **转发给渠道时使用此值**

## 四、关键发现与规律

### 4.1 Click ID 转换规律

| 阶段 | Click ID值 | 来源 | 用途 |
|------|-----------|------|------|
| 渠道点击 | `1230180` | 渠道提供 | 保存到url_params |
| 系统生成 | `bpt7KMtEX497DrdtKWMPMweTXEYA4wKkpmbhFjHE` | 系统生成 | 内部追踪、跳转广告主 |
| 广告主Postback | `bpt7KMtEX497DrdtKWMPMweTXEYA4wKkpmbhFjHE` | 广告主返回 | 匹配转化记录 |
| 转发给渠道 | `1230180` | 从url_params提取 | 渠道识别自己的转化 |

**规律总结：**
- 系统内部使用系统生成的click_id进行追踪
- 转发给渠道时使用渠道原始click_id
- 通过 `clicks.url_params` 字段实现两种ID的映射

### 4.2 Payout 扣减规律

| 阶段 | Payout值 | 说明 |
|------|---------|------|
| 广告主Postback | `2.80` | 原始payout（PO） |
| 扣减后 | `2.42` | 扣减后payout（PO(扣)） |
| 转发给渠道 | `2.42` | 使用扣减后的值 |

**规律总结：**
- 原始payout保存到 `postback_conversions.original_payout`
- 扣减后payout保存到 `postback_conversions.payout`
- 转发给渠道时使用扣减后的payout

### 4.3 占位符替换规律

| 占位符 | 替换值来源 | 实际案例 |
|--------|----------|---------|
| `{click_id}` | 从 `clicks.url_params` 提取渠道原始click_id | `1230180` |
| `{payout}` | 使用 `conversion.payout`（扣减后的值） | `2.42` |
| `{original_payout}` | 使用 `conversion.original_payout`（原始值） | `2.80` |

**规律总结：**
- 转发URL中的 `{click_id}` 使用渠道原始click_id（不是系统生成的）
- 转发URL中的 `{payout}` 使用扣减后的payout（不是原始的）
- 如果需要原始payout，可以使用 `{original_payout}` 占位符

## 六、总结

### 6.1 核心原理

1. **Click ID双重身份机制**
   - 系统生成click_id用于内部追踪和广告主跳转
   - 渠道原始click_id保存到url_params，用于转发给渠道

2. **Payout扣减机制**
   - 原始payout保存到original_payout字段
   - 扣减后payout保存到payout字段
   - 转发给渠道时使用扣减后的payout

3. **占位符替换机制**
   - `{click_id}` 使用渠道原始click_id（从url_params提取）
   - `{payout}` 使用扣减后的payout
   - `{original_payout}` 使用原始payout

### 6.2 数据流转

```
渠道点击（click_id=1230180）
  ↓
系统生成新click_id（bpt7KMtEX497DrdtKWMPMweTXEYA4wKkpmbhFjHE）

跳转广告主（使用系统生成的click_id）
  ↓
广告主Postback（payout=2.80）
  ↓
应用扣减（payout=2.42）
  ↓
转发给渠道（使用渠道原始click_id + 扣减后的payout）
```
