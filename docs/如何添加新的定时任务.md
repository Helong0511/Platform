# 如何添加新的定时任务

本文档说明如何添加新的定时任务，并确保执行结果能正确显示在"最后错误"栏中。

## 步骤1：在任务名称配置文件中添加新任务名称

在 `app/scheduler_module/task_names.py` 中添加新任务的名称常量：

```python
# 新任务名称
MY_NEW_TASK_NAME = "新任务名称"
```

**重要**：这个名称必须与数据库中的 `task_name` 完全一致！

## 步骤2：创建任务文件

1. 复制模板文件 `app/scheduler_module/tasks/_task_template.py`
2. 重命名为你的任务名称，例如：`my_new_task.py`
3. 将文件放在 `app/scheduler_module/tasks/` 目录下

## 步骤3：修改任务代码

在新建的任务文件中：

1. **导入必要的模块**：
   ```python
   from app.scheduler_module.task_names import MY_NEW_TASK_NAME
   from app.scheduler_module.task_utils import (
       log_task_start,      # 记录任务开始
       log_task_result,      # 记录任务结果
       log_task_error,       # 记录任务错误
       format_result_summary,  # 格式化结果摘要
   )
   ```

2. **修改任务函数名称**：
   ```python
   async def my_new_task() -> None:  # 改为你的任务函数名
   ```

3. **使用工具函数简化代码**：
   ```python
   # 记录任务开始（使用工具函数，自动格式化时间）
   log_task_start(MY_NEW_TASK_NAME)
   
   # 格式化结果摘要（使用工具函数，自动处理各种统计项）
   result_summary = format_result_summary(
       inserted=10,
       updated=5,
       skipped=2,
       error=1
   )
   # 输出：'成功插入 10 条, 成功更新 5 条, 跳过重复 2 条, 错误 1 条'
   
   # 记录任务结果（使用工具函数）
   log_task_result(MY_NEW_TASK_NAME, result_summary, level="warning")
   
   # 保存执行结果
   set_task_result(MY_NEW_TASK_NAME, f"执行成功: {result_summary}")
   ```

4. **错误处理**：
   ```python
   except Exception as e:
       # 使用工具函数记录错误
       log_task_error(MY_NEW_TASK_NAME, str(e), exc_info=True)
       raise
   ```

4. **错误处理**：
   - 在 `except Exception as e:` 块中处理错误
   - 使用 `raise` 重新抛出异常，让调度器记录错误状态

## 步骤4：注册任务函数

在 `app/scheduler_module/task_registry.py` 的 `auto_register_tasks()` 函数中添加：

```python
# 导入任务名称常量
from app.scheduler_module.task_names import MY_NEW_TASK_NAME

# 注册新任务
from app.scheduler_module.tasks.my_new_task import my_new_task
register_task_function(MY_NEW_TASK_NAME, my_new_task)
```

## 步骤5：注册结果获取函数

在 `app/scheduler_module/task_result_registry.py` 的 `auto_register_task_results()` 函数中添加：

```python
# 导入任务名称常量
from app.scheduler_module.task_names import MY_NEW_TASK_NAME

# 注册新任务的结果获取函数
try:
    from app.scheduler_module.tasks.my_new_task import get_task_result as my_new_task_get_result
    register_task_result_getter(MY_NEW_TASK_NAME, my_new_task_get_result)
except ImportError:
    logger.warning("无法导入新任务结果获取函数")
```

## 步骤6：在数据库中创建任务记录

在数据库的 `scheduled_tasks` 表中插入新记录：

```sql
INSERT INTO `scheduled_tasks` (
    `task_name`,           -- 任务名称（必须与代码中的名称一致）
    `description`,         -- 任务描述
    `cron_expression`,    -- Cron表达式（如：'*/30 * * * *' 表示每30分钟）
    `function_path`,      -- 函数路径（如：'app.scheduler_module.tasks.my_new_task.my_new_task'）
    `is_active`,          -- 是否激活（1=激活，0=禁用）
    `created_at`,
    `updated_at`
) VALUES (
    '新任务名称',
    '任务描述信息',
    '*/30 * * * *',
    'app.scheduler_module.tasks.my_new_task.my_new_task',
    1,
    NOW(),
    NOW()
);
```

## 步骤7：重启服务

重启应用服务，新任务会自动注册并开始执行。

## 执行结果显示

任务执行完成后，结果会自动显示在"最后错误"栏中：

- **成功时**：显示 `执行成功: 成功处理 X 条, 错误 Y 条`
- **失败时**：显示错误信息

## 注意事项

1. **任务名称必须一致**：
   - `task_names.py` 中定义的常量值
   - 代码中的 `set_task_result()` 使用的名称（应使用常量）
   - `task_registry.py` 中注册的名称（应使用常量）
   - `task_result_registry.py` 中注册的名称（应使用常量）
   - 数据库中的 `task_name`
   
   **最佳实践**：所有地方都使用 `task_names.py` 中的常量，这样只需在一个地方修改！

2. **使用工具函数**：
   - 使用 `log_task_start()` 记录任务开始，而不是手动格式化时间
   - 使用 `format_result_summary()` 格式化结果摘要，而不是手动拼接字符串
   - 使用 `log_task_result()` 和 `log_task_error()` 记录结果和错误
   - 这样可以减少重复代码，保持日志格式一致

3. **使用任务名称常量**：
   - 不要硬编码任务名称字符串
   - 始终从 `task_names.py` 导入并使用常量
   - 这样修改任务名称时，只需在 `task_names.py` 中修改一次

4. **结果摘要格式**：
   - 使用 `format_result_summary()` 函数格式化结果
   - 支持常见统计项：inserted, updated, skipped, error, success, processed
   - 可以通过 `**kwargs` 添加自定义统计项

2. **结果格式建议**：
   - 成功：`执行成功: 成功处理 X 条, 错误 Y 条`
   - 无数据：`执行成功: 暂无数据`
   - 失败：会自动显示错误信息

3. **日志记录**：
   - 使用 `logger.info()` 记录一般信息
   - 使用 `logger.warning()` 记录重要信息（确保可见）
   - 使用 `logger.error()` 记录错误信息

4. **异步函数**：
   - 任务函数必须是 `async def` 异步函数
   - 可以使用 `await` 调用异步操作

## 常见问题

**Q: 任务执行了，但"最后错误"栏没有显示结果？**
A: 检查任务名称是否在所有地方都一致，以及是否正确调用了 `set_task_result()`。

**Q: 如何测试新任务？**
A: 可以在数据库中手动设置任务的 `cron_expression` 为 `* * * * *`（每分钟执行），测试完成后改回正常频率。

**Q: 任务执行失败怎么办？**
A: 查看日志文件 `logs/app.log`，查找对应的错误信息。确保异常被正确抛出（使用 `raise`）。
