# 生产环境配置指南

## 概述

本文档详细说明如何配置生产环境的 `.env.production` 文件，确保系统安全、稳定运行。

## 快速开始

### 1. 创建配置文件

```bash
# 复制模板文件
cp .env.production.example .env.production

# 设置文件权限（仅所有者可读写）
chmod 600 .env.production
```

### 2. 修改必须配置项

使用文本编辑器打开 `.env.production`，修改以下**必须修改**的配置项：

#### 安全配置

```bash
# 生成强随机密钥（64字符）
python -c "import secrets; print(secrets.token_urlsafe(64))"

# 将生成的密钥设置到 SECRET_KEY
SECRET_KEY=<生成的密钥>
```

#### 数据库配置

```bash
# MySQL 根密码（至少16字符）
MYSQL_ROOT_PASSWORD=<强密码>

# MySQL 应用用户密码（至少16字符）
MYSQL_PASSWORD=<强密码>
```

#### Redis 配置

```bash
# Redis 密码（至少16字符）
REDIS_PASSWORD=<强密码>
```

#### CORS 配置

```bash
# 设置为实际的前端域名（必须使用 HTTPS）
BACKEND_CORS_ORIGINS=https://your-domain.com,https://www.your-domain.com
```

#### 管理员账户

```bash
# 管理员密码（至少12字符）
FIRST_SUPERUSER_PASSWORD=<强密码>
```

### 3. 验证配置

启动应用前，运行配置验证：

```bash
# 检查配置文件格式
python -c "from dotenv import load_dotenv; load_dotenv('.env.production'); print('配置加载成功')"
```

## 配置项详解

### 环境配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `PRODUCTION_ENV` | 环境标识 | `production` | 否 |

### 安全配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `SECRET_KEY` | JWT签名密钥 | - | **是** |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Token过期时间（分钟） | `240` | 否 |

**SECRET_KEY 生成方法：**

```bash
# Python 方式（推荐）
python -c "import secrets; print(secrets.token_urlsafe(64))"

# OpenSSL 方式
openssl rand -base64 64
```

### 数据库配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `MYSQL_ROOT_PASSWORD` | MySQL根密码 | - | **是** |
| `MYSQL_DATABASE` | 数据库名称 | `platform` | 否 |
| `MYSQL_USER` | 应用用户 | `platform_user` | 建议 |
| `MYSQL_PASSWORD` | 应用用户密码 | - | **是** |
| `MYSQL_PORT` | MySQL端口 | `3306` | 否 |
| `DB_POOL_SIZE` | 连接池大小 | `15` | 否 |
| `DB_MAX_OVERFLOW` | 最大溢出连接 | `10` | 否 |
| `DB_POOL_RECYCLE` | 连接回收时间（秒） | `3600` | 否 |

**连接池配置建议：**

- 总连接数 = `(DB_POOL_SIZE + DB_MAX_OVERFLOW) × WORKERS`
- 例如：`(15 + 10) × 3 = 75` 个连接
- 确保总连接数不超过 MySQL 的 `max_connections`（默认151）

### Redis 配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `REDIS_HOST` | Redis主机 | `redis` | 否 |
| `REDIS_PORT` | Redis端口 | `6379` | 否 |
| `REDIS_DB` | 数据库编号 | `0` | 否 |
| `REDIS_PASSWORD` | Redis密码 | - | **是** |
| `REDIS_MAX_CONNECTIONS` | 最大连接数 | `10` | 否 |

### CORS 配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `BACKEND_CORS_ORIGINS` | 允许的跨域来源 | - | **是** |

**配置格式：**

```bash
# 单个域名
BACKEND_CORS_ORIGINS=https://example.com

# 多个域名（逗号分隔，无空格）
BACKEND_CORS_ORIGINS=https://example.com,https://www.example.com
```

**重要提示：**

- 生产环境**不能**包含 `localhost` 或 `127.0.0.1`
- 建议使用 HTTPS
- 多个域名用逗号分隔，不要有空格

### 管理员账户配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `FIRST_SUPERUSER` | 管理员用户名 | `admin` | 建议 |
| `FIRST_SUPERUSER_PASSWORD` | 管理员密码 | - | **是** |

**密码要求：**

- 至少12个字符
- 不能使用默认密码 `admin123`
- 建议包含大小写字母、数字和特殊字符

### API 限流配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `API_RATE_LIMIT` | 默认限流（每分钟） | `100` | 否 |
| `LOGIN_RATE_LIMIT` | 登录限流（每分钟） | `5` | 否 |

**限流说明：**

- 限流基于 IP 地址
- `API_RATE_LIMIT`：适用于所有 API 接口
- `LOGIN_RATE_LIMIT`：仅适用于登录接口（防止暴力破解）

### CSRF 防护配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `ENABLE_CSRF` | 是否启用CSRF防护 | `true` | 否 |
| `CSRF_TOKEN_EXPIRE_SECONDS` | CSRF令牌过期时间（秒） | `3600` | 否 |

**建议：**

- 生产环境**强烈建议**启用 CSRF 防护
- 仅在特殊情况下（如纯 API 服务）可禁用

### Gunicorn 配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `WORKERS` | Worker数量 | `3` | 建议 |
| `PRELOAD_APP` | 是否预加载应用 | `true` | 否 |

**Worker 数量计算：**

```
推荐公式：workers = (2 × CPU核心数) + 1
```

示例：
- 2核CPU → 5 workers
- 4核CPU → 9 workers
- 8核CPU → 17 workers

**注意：**

- 每个 worker 会占用内存（约 100-200MB）
- 需要根据服务器内存调整
- 预加载应用（`PRELOAD_APP=true`）可提高性能，但增加内存使用

### 日志配置

| 配置项 | 说明 | 默认值 | 必须修改 |
|--------|------|--------|----------|
| `LOG_LEVEL` | 日志级别 | `INFO` | 否 |
| `LOG_FILE` | 日志文件路径 | `logs/app.log` | 否 |
| `LOG_MAX_BYTES` | 日志文件最大大小（字节） | `10485760` | 否 |
| `LOG_BACKUP_COUNT` | 日志备份数量 | `5` | 否 |

**日志级别说明：**

- `DEBUG`：详细调试信息（仅开发环境）
- `INFO`：一般信息（推荐生产环境）
- `WARNING`：警告信息（减少日志量）
- `ERROR`：错误信息
- `CRITICAL`：严重错误

## 配置验证清单

部署前请确认以下配置已正确设置：

- [ ] `SECRET_KEY`：已设置为强随机密钥（至少32字符）
- [ ] `MYSQL_ROOT_PASSWORD`：已设置为强密码
- [ ] `MYSQL_PASSWORD`：已设置为强密码
- [ ] `REDIS_PASSWORD`：已设置为强密码
- [ ] `FIRST_SUPERUSER_PASSWORD`：已设置为强密码（至少12字符）
- [ ] `BACKEND_CORS_ORIGINS`：已设置为实际的前端域名（不包含localhost）
- [ ] `PRODUCTION_ENV`：已设置为 `production`
- [ ] `LOG_LEVEL`：已设置为 `INFO` 或 `WARNING`
- [ ] `WORKERS`：已根据服务器配置调整
- [ ] 所有密码都不再使用默认值

## 安全最佳实践

### 1. 密钥管理

- ✅ 使用密钥管理服务（AWS Secrets Manager、HashiCorp Vault）
- ✅ 定期轮换密码和密钥（建议每3-6个月）
- ✅ 不要将配置文件提交到版本控制系统
- ✅ 使用 `.gitignore` 排除 `.env.production`

### 2. 网络安全

- ✅ 使用 HTTPS 加密传输
- ✅ 配置防火墙，限制数据库和 Redis 端口访问
- ✅ 使用反向代理（Nginx）隐藏后端服务
- ✅ 限制管理端口访问（仅内网或VPN）

### 3. 数据库安全

- ✅ 使用强密码（至少16字符）
- ✅ 限制数据库用户权限（应用用户只授予必要权限）
- ✅ 定期备份数据库
- ✅ 启用数据库审计日志
- ✅ 不暴露数据库端口到公网

### 4. Redis 安全

- ✅ 设置强密码
- ✅ 限制 Redis 端口访问（仅内网）
- ✅ 考虑使用 Redis ACL（Redis 6.0+）
- ✅ 不暴露 Redis 端口到公网

### 5. 应用安全

- ✅ 启用 CSRF 防护
- ✅ 配置合理的限流策略
- ✅ 定期更新依赖包
- ✅ 监控异常访问和错误日志
- ✅ 使用 HTTPS（强制重定向 HTTP 到 HTTPS）

### 6. 运维安全

- ✅ 使用非 root 用户运行容器
- ✅ 限制容器资源使用（CPU、内存）
- ✅ 配置日志轮转和清理策略
- ✅ 定期检查安全更新
- ✅ 监控系统资源使用情况

## 部署步骤

### 1. 准备配置文件

```bash
# 复制模板
cp .env.production.example .env.production

# 编辑配置
vim .env.production  # 或使用其他编辑器

# 设置权限
chmod 600 .env.production
```

### 2. 验证配置

```bash
# 检查配置格式
python -c "from dotenv import load_dotenv; load_dotenv('.env.production'); print('配置加载成功')"
```

### 3. 启动服务

```bash
# 使用 systemd（推荐）
sudo systemctl start platform-backend
sudo systemctl enable platform-backend

# 或使用 Gunicorn 直接启动
gunicorn app.main:app -c gunicorn.conf.py
```

### 4. 验证部署

```bash
# 检查服务状态
sudo systemctl status platform-backend

# 查看日志
tail -f logs/app.log

# 检查健康状态
curl http://localhost:8960/health
```

## 故障排查

### 配置加载失败

**问题：** 应用启动时提示配置错误

**解决方案：**

1. 检查配置文件格式（确保没有语法错误）
2. 检查文件编码（必须是 UTF-8）
3. 检查文件权限（建议 600）
4. 查看应用日志获取详细错误信息

### 数据库连接失败

**问题：** 无法连接到数据库

**解决方案：**

1. 检查 `DATABASE_URL` 格式是否正确
2. 检查数据库服务是否运行
3. 检查数据库用户权限
4. 检查网络连接（防火墙、端口）

### Redis 连接失败

**问题：** 无法连接到 Redis

**解决方案：**

1. 检查 Redis 服务是否运行
2. 检查 Redis 密码是否正确
3. 检查网络连接
4. 如果 Redis 不可用，应用会自动降级到内存存储（但多进程环境可能不一致）

### CORS 错误

**问题：** 前端请求被 CORS 策略阻止

**解决方案：**

1. 检查 `BACKEND_CORS_ORIGINS` 是否包含前端域名
2. 确保前端域名使用 HTTPS（生产环境）
3. 检查域名格式（不能有空格）
4. 查看浏览器控制台获取详细错误信息
